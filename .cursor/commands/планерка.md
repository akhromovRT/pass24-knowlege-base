# Планерка — Автоматическое создание протокола еженедельной планерки

Автоматически создает протокол еженедельной планерки по стратегии на основе транскрипта совещания. Анализирует материалы распознанные после планерки, заполняет протокол по структуре шаблона и добавляет информацию, обсуждавшуюся помимо повестки.

**Автор команды:** Система автоматизации протоколов планерки

## Когда использовать

- После проведения еженедельной планерки по стратегии
- Для автоматического создания протокола на основе транскрипта
- Для структурирования информации из совещания по стандартному формату
- Для отслеживания прогресса по стратегическим целям

## Требования

- Транскрипт планерки (текст или ссылка на материалы)
- Шаблон протокола: `База знаний/01 О компании/06 Стратегия 2026/Еженедельная планерка/Повестка и протокол еженедельной планерки.md`
- Дата планерки (формат: ГГГГ-ММ-ДД)

## Инструкции

### Шаг 1: Получить транскрипт планерки

Пользователь может предоставить:
- Текст транскрипта напрямую в сообщении
- Ссылку на материалы (например, plaud.ai)
- Путь к файлу с транскриптом

**Примеры:**
- Прямой текст транскрипта в сообщении
- Ссылка: `https://web.plaud.ai/s/pub_...`
- Файл: `@транскрипт-планерки.md`

**Действия:**
1. Если предоставлена ссылка — получить содержимое по ссылке
2. Если предоставлен файл — прочитать файл
3. Если предоставлен текст — использовать текст напрямую

### Шаг 2: Определить дату планерки

**Варианты:**
1. Пользователь явно указал дату (например: "02-02-2026" или "2026-02-02")
2. Дата указана в транскрипте (искать в начале текста)
3. Использовать текущую дату, если не указана

**Формат даты:** ГГГГ-ММ-ДД (например: 2026-02-02)

**Имя файла протокола:** `ДД-ММ-ГГ-Планерка.md` (например: `02-02-26-Планерка.md`)

### Шаг 3: Прочитать шаблон протокола

**Путь к шаблону:**
```
База знаний/01 О компании/06 Стратегия 2026/Еженедельная планерка/Повестка и протокол еженедельной планерки.md
```

**Что извлечь из шаблона:**
- Структуру протокола (разделы и подразделы)
- Формат таблиц (реквизиты, цели, метрики, блокеры, действия)
- Повестку планерки (вопросы по каждой цели)
- Расшифровку светофоров (🟢🟡🔴)

### Шаг 4: Проанализировать транскрипт

**Извлечь из транскрипта:**

1. **Реквизиты:**
   - Участники (имена, должности)
   - Отсутствовавшие
   - Ответственный за протокол
   - Дата и время следующей планерки

2. **Результаты по целям (5 стратегических целей):**
   - Цель 1: Ускорить продажу PASS24.Cloud (KPI: Цикл сделки < 14 дней)
   - Цель 2: Упаковать стандарт Cloud для КП (KPI: 1 оффер · 1 сценарий · 1 КП)
   - Цель 3: Повторяемая машина продаж (KPI: ≥10 новых подключений/мес)
   - Цель 4: Снять узкие места согласований (KPI: ТОП-5 стоп-факторов → решения)
   - Цель 5: Дисциплина исполнения (KPI: Совещания + квартальные апдейты)
   
   Для каждой цели определить:
   - Светофор (🟢 / 🟡 / 🔴)
   - Текущее значение / факт за период
   - Комментарий

3. **Верхнеуровневые метрики:**
   - Клиенты КП (постоянно регулярно платящие)
   - MRR
   - Новых подключений в текущем месяце
   - Churn rate
   - NPS

4. **Блокеры:**
   - Описание блокера
   - Владелец решения
   - Желаемый результат / срок

5. **Принятые решения:**
   - Решение
   - Контекст (кратко)

6. **Действия на следующую неделю:**
   - Действие
   - Ответственный
   - Срок
   - Ожидаемый результат

7. **Дополнительные темы (помимо повестки):**
   - Итоги продаж
   - Маркетинг
   - Стратегические партнерства
   - Другие обсужденные темы

### Шаг 5: Заполнить реквизиты протокола

**Создать таблицу реквизитов:**

```markdown
## Реквизиты протокола

| Поле | Значение |
|------|----------|
| **Дата планерки** | [дата в формате ГГГГ-ММ-ДД] |
| **Участники** | [список участников из транскрипта] |
| **Отсутствовали** | [если указано в транскрипте] |
| **Ответственный за протокол** | [из транскрипта или определить] |
| **Следующая планерка** | [дата и время из транскрипта] |
```

**Извлечь из транскрипта:**
- Имена участников (искать упоминания: "Алексей Хромов", "Павел", "Дмитрий" и т.д.)
- Ответственного за протокол (часто указывается в конце)
- Дату следующей планерки (искать фразы: "следующая планерка", "следующий понедельник")

### Шаг 6: Заполнить результаты по целям

**Для каждой из 5 целей:**

1. **Проанализировать обсуждение в транскрипте:**
   - Найти упоминания цели или связанных метрик
   - Определить текущее состояние
   - Выявить проблемы и достижения

2. **Определить светофор:**
   - 🟢 (зеленый) — по плану, все хорошо
   - 🟡 (желтый) — есть риски, но работа идет
   - 🔴 (красный) — под угрозой, требуется вмешательство

3. **Заполнить метрики:**
   - Извлечь конкретные цифры и факты
   - Сравнить с целевыми показателями
   - Добавить комментарии

**Пример анализа для Цели 1 (Ускорить продажу PASS24.Cloud):**
- Искать в транскрипте: "цикл сделки", "14 дней", "продажи", "сделки"
- Извлечь: количество сделок, процент быстрых сделок, узкие места
- Определить светофор на основе данных

### Шаг 7: Заполнить детализацию по повестке

**Для каждого раздела повестки создать детализацию:**

1. **Якорь и фокус:**
   - Проверить соответствие действий стратегическому фокусу
   - Выявить инициативы вне фокуса

2. **Цель 1-5:** Для каждой цели:
   - Ответы на вопросы повестки (2.1, 2.2, 2.3, 2.4 и т.д.)
   - Выводы по цели

3. **Верхнеуровневые метрики:**
   - Краткий срез метрик
   - Комментарии к метрикам

4. **Блокеры и риски:**
   - Список блокеров с владельцами и сроками
   - Выявленные риски

5. **Решения и действия:**
   - Принятые решения
   - Действия на следующую неделю с ответственными и сроками

### Шаг 8: Извлечь задачи к исполнению

**Найти в транскрипте раздел "Задачи к исполнению" или "Action Items":**

**Формат задач:**
- `@Ответственный - Описание задачи. - Срок: [дата]`

**Создать таблицу действий:**

```markdown
| № | Действие | Ответственный | Срок | Ожидаемый результат |
|---|----------|----------------|------|----------------------|
| 1 | [описание] | [имя] | ГГГГ-ММ-ДД | [результат] |
```

**Обработать каждую задачу:**
- Извлечь ответственного (после @)
- Извлечь описание задачи
- Определить срок (если указан)
- Определить ожидаемый результат (если указан)

### Шаг 9: Извлечь ключевые решения

**Найти в транскрипте раздел "Ключевые решения" или "Key Decisions":**

**Создать таблицу решений:**

```markdown
| № | Решение | Контекст (кратко) |
|---|---------|-------------------|
| 1 | [решение] | [контекст] |
```

**Обработать каждое решение:**
- Извлечь суть решения
- Добавить краткий контекст (рационализация, причина)

### Шаг 10: Заполнить дополнительные темы

   - Прогнозы

2. **Маркетинг:**
   - Выводы с конференций
   - Маркетинговые материалы

## Обработка ошибок

**Если транскрипт не найден:**
1. Проверить правильность ссылки или пути к файлу
2. Попросить пользователя предоставить транскрипт напрямую
3. Если транскрипт недоступен, создать протокол с пометками "[Требуется заполнить]"

**Если шаблон не найден:**
1. Проверить наличие файла `Повестка и протокол еженедельной планерки.md`
2. Использовать структуру из инструкции выше

**Если дата не указана:**
1. Попросить пользователя указать дату
2. Или использовать текущую дату с пометкой

**Если информация неполная:**
1. Заполнить доступные разделы
2. Оставить пометки "[Требуется заполнить]" для недостающей информации
3. Указать в примечаниях, что протокол требует доработки

## Примечания

- **Время обработки:** Зависит от длины транскрипта и количества информации
- **Структура:** Протокол создаётся по стандарту из шаблона планерки
- **Автоматизация:** Команда автоматически извлекает задачи, решения, метрики из транскрипта
- **Формат:** Все данные структурированы в табличном виде для удобства отслеживания
