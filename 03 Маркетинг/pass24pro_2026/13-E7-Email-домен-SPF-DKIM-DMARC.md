## Краткое описание

Документ описывает текущую схему email-рассылок PASS24, план настройки SPF / DKIM / DMARC, чеклист проверки и регламент поддержки. Цель — обеспечить попадание писем во входящие, а не в спам.

## Шаг 1. Инвентаризация текущей схемы

> ⚠️ Заполнить данными из реальной инфраструктуры

### Сервисы рассылок

| Сервис | Назначение | Домен отправителя | Статус |
|--------|------------|-------------------|--------|
| [Сервис 1, напр. Unisender / SendPulse] | Массовые рассылки | [from@...] | [Настроен / Нет] |
| [Сервис 2, напр. SMTP собственный] | Транзакционные письма | [noreply@...] | [Настроен / Нет] |
| [Сервис 3, напр. Bitrix] | CRM-уведомления | [bitrix@...] | [Настроен / Нет] |

### Текущие DNS-записи для проверки

Для домена `pass24.online` (и/или `pass24pro.ru`) проверить наличие:

```
# Проверка SPF
dig TXT pass24.online | grep spf

# Проверка DKIM (имя селектора уточнить в сервисе рассылок)
dig TXT [selector]._domainkey.pass24.online

# Проверка DMARC
dig TXT _dmarc.pass24.online
```

Или использовать онлайн-инструменты:
- MXToolbox: https://mxtoolbox.com/SuperTool.aspx
- Mail-Tester: https://www.mail-tester.com
- Google Postmaster Tools (для Gmail)

## Шаг 2. Выбор схемы доменов

### Рекомендуемая схема

| Тип писем | Домен отправителя | Обоснование |
|-----------|-------------------|-------------|
| Массовые рассылки (маркетинг) | `news@pass24.online` или `hello@pass24pro.ru` | Отдельный поддомен снижает риск порчи репутации основного домена |
| Транзакционные (уведомления, счета) | `noreply@pass24.online` | Отдельный поток, другой приоритет |
| CRM / Sales AI | `[имя менеджера]@pass24.online` | Персонализация повышает открываемость |

> **Решение:** Использовать поддомен `mail.pass24.online` для массовых рассылок — если основной домен ещё не «прогрет».

## Шаг 3. Настройка SPF

SPF (Sender Policy Framework) — указывает, какие серверы вправе отправлять почту от имени домена.

### Шаблон записи

```
Тип:  TXT
Хост: @  (или поддомен, напр. mail)
Значение: v=spf1 include:[сервис_рассылок] include:[smtp_сервер] ~all
```

### Пример для Unisender

```
v=spf1 include:spf.unisender.com ~all
```

### Пример для нескольких сервисов

```
v=spf1 include:spf.unisender.com include:_spf.google.com ip4:[IP_своего_SMTP] ~all
```

> ⚠️ Нельзя создавать несколько TXT-записей SPF на одном домене — объединять в одну строку.

### Чеклист проверки SPF

- [ ] Запись создана в DNS-панели
- [ ] TTL установлен 300–3600 сек
- [ ] Проверка: `dig TXT [домен]` показывает `v=spf1 ...`
- [ ] MXToolbox SPF Check — статус Pass
- [ ] Тестовое письмо с заголовком `Authentication-Results: ... spf=pass`

## Шаг 4. Настройка DKIM

DKIM (DomainKeys Identified Mail) — цифровая подпись письма публичным ключом домена.

### Получить ключи

1. В сервисе рассылок найти раздел «Домены» → «DKIM»
2. Сервис предоставит:
   - Имя селектора (напр. `unisender`)
   - CNAME или TXT запись для добавления в DNS

### Шаблон записи

```
Тип:  TXT (или CNAME — зависит от сервиса)
Хост: [selector]._domainkey.[домен]
Значение: v=DKIM1; k=rsa; p=[публичный_ключ]
```

### Чеклист проверки DKIM

- [ ] Запись создана в DNS
- [ ] Ожидание распространения DNS (до 48 ч, обычно 1–2 ч)
- [ ] MXToolbox DKIM Check — статус Valid
- [ ] Тестовое письмо: заголовок `dkim=pass (signature verified)`
- [ ] В сервисе рассылок статус домена — «Подтверждён»

## Шаг 5. Настройка DMARC

DMARC (Domain-based Message Authentication, Reporting & Conformance) — политика обработки писем, не прошедших SPF или DKIM.

### Рекомендуемый старт (мягкая политика)

```
Тип:  TXT
Хост: _dmarc.[домен]
Значение: v=DMARC1; p=none; rua=mailto:dmarc-reports@[домен]; ruf=mailto:dmarc-failures@[домен]; fo=1
```

| Параметр | Значение | Описание |
|----------|----------|----------|
| `p=none` | Мониторинг без блокировки | Безопасный старт — не блокирует письма |
| `p=quarantine` | Спам | Включить после 2–4 нед. мониторинга |
| `p=reject` | Блокировка | Только после уверенности в чистоте SPF/DKIM |
| `rua=` | Адрес агрегированных отчётов | Отчёты о доставке |
| `fo=1` | Отчёты при любом сбое | Помогает диагностировать проблемы |

### Путь к строгой политике

```
p=none → (2–4 недели мониторинга) → p=quarantine → (2–4 недели) → p=reject
```

### Чеклист проверки DMARC

- [ ] Запись создана
- [ ] MXToolbox DMARC Check — Valid
- [ ] Начали приходить отчёты на `rua` адрес (в течение 24–72 ч)
- [ ] Отчёты проанализированы — нет легитимных источников с fail

### Чеклист финального теста

- [ ] Ссылки в письме не содержат заблокированных доменов
- [ ] Ссылка отписки работает

## Шаг 8. Регламент поддержки и управления

### Кто управляет DNS

| Действие | Ответственный | Где |
|----------|---------------|-----|
| Создание / изменение TXT-записей | [Системный администратор / DevOps] | [DNS-панель: Reg.ru / Cloudflare / другое] |
| Добавление нового сервиса рассылок | Маркетинг + Администратор | Обновить SPF + добавить DKIM |
| Экстренный фикс при провале SPF | Администратор | Приоритет 1, реакция <4 часов |

### Как добавить нового отправителя

1. Получить от сервиса рассылок:
   - Значение `include:` для SPF
   - DKIM-запись (TXT или CNAME)
2. Добавить `include:` в существующую SPF-запись (не создавать новую)
3. Добавить DKIM-запись
4. Верифицировать домен в новом сервисе
5. Провести тест (mail-tester.com)
6. Обновить таблицу сервисов в этом документе
