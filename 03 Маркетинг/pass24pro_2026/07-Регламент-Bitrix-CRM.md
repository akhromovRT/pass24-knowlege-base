## Основной контент

### 1. Работа с лидами

#### 1.1. Откуда берутся лиды

Лид в Bitrix создаётся автоматически или вручную по одному из каналов:

| Канал | Описание |
|-------|---------|
| **Старый сайт pass24online.ru** | Формы заявки, обратного звонка, демо и другие веб-формы |
| **Новый сайт pass24pro.ru** | Формы заявки, обратной связи, демо-заявки, чаты, AI-агенты |
| **Телефонные звонки** | Входящие звонки по основным номерам компании |
| **Email** | Входящие письма на корпоративные адреса |
| **Партнёрские каналы** | Лиды от интеграторов, подрядчиков, партнёров |
| **Marketplace PASS24** | Заявки из pass24market.ru |

> **Правило:** Все лиды, независимо от канала, попадают в единый лид-pipeline Bitrix с обязательным указанием источника.

---

#### 1.2. Карточка лида — обязательные поля

**Блок «Контакт»:**
- Имя
- Телефон
- Email
- Компания
- Адрес объекта
- Ответственный менеджер

**Блок «Объект»:**
- Тип объекта (ЖК, КП, БЦ, Склад, Производство и т.д.)
- Количество точек прохода
- Количество КПП
- Какое оборудование уже есть
- Какой функционал необходим

**Блок «Источник и аналитика»:**
- SOURCE_CHANNEL (канал: сайт, звонок, email, партнёр)
- SOURCE_DETAIL (конкретный источник внутри канала)
- FROM_PAGE (страница, с которой пришла заявка)
- UTM-метки (utm_source, utm_medium, utm_campaign, utm_content, utm_term)
- «Откуда узнали?» (текстовое поле для нестандартных источников)

> ⚠️ Поля «Объект» и «Источник» должны быть заполнены **до перевода лида в статус «Успешно»**.

---

#### 1.3. Воронка лида — статусы

| Статус | Описание |
|--------|---------|
| **Новая заявка** | Лид только что создан (форма, звонок, marketplace) |
| **В работе** | Есть первый контакт или попытка, собираются данные по объекту |
| **НДЗ** (Не дозвониться) | 1–2 безуспешные попытки, фиксируются дата и количество |
| **Некачественный лид** | Нецелевая заявка |
| **Реклама и сотрудничество** | Коммерческое предложение от партнёров |
| **Реклама/СПАМ** | Спам |
| **Ошибка** | Техническая ошибка при создании |
| **Повторный лид** | Дублирует существующий контакт |
| **Тест** | Тестовая заявка |
| **Техподдержка** | Вопрос в техподдержку, не продажа |
| **Прочее** | Другие причины неквалификации |
| **Успешно** | Лид признан целевым, создаётся сделка |

> **Правило:** Перевод в финальные статусы всегда сопровождается **коротким комментарием**.

---

#### 1.4. Критерии квалификации лида

Лид считается квалифицированным и может быть переведён в «Успешно», если:

- ✅ Заполнены контактные данные (Имя, Телефон, Компания или контактное лицо)
- ✅ Заполнены ключевые параметры объекта (Тип объекта, точки прохода, КПП, оборудование, функционал)
- ✅ Понятно, кто принимает решение и в какие сроки планируется внедрение
- ✅ Источник и UTM указаны корректно (или осознанно отмечено «сарафанное радио / рекомендация»)

**Схема пути лида:**
```
Источник → Лид в Bitrix → Квалификация → Сделка → Реализация / Отказ
```

### 2. Работа со сделками

#### 2.1. Воронка сделок

| Стадия | Описание |
|--------|---------|
| **Новая сделка** | Создана из квалифицированного лида, определены объект и запрос |
| **Квалификация / Обследование** | Сбор технических данных, аудит инфраструктуры |
| **ТКП** | Расчёт стоимости, отправка технико-коммерческого предложения |
| **Переговоры** | Обсуждение условий, сроков, формата внедрения / пилота |
| **Договор / Согласование** | Подготовка и подписание договора |
| **Реализация / Внедрение** | Техническое подключение, настройка, обучение, запуск |
| **Успешно реализовано** | Проект запущен, объект передан в сопровождение |
| **Закрыта неуспешно** | Причина отказа фиксируется в отдельном поле |

---

#### 2.2. Связь сделки с объектом и контактами

- Каждая сделка должна быть связана с **Контактом**, **Компанией** и **Объектом** (ЖК/КП/БЦ и т.п.)
- Рекомендуется использовать отдельную сущность «Объект» и привязывать к ней все сделки по данному объекту

---

#### 2.3. Правила ведения сделок

- Сделка всегда находится ровно в **одной актуальной стадии**
- При каждом значимом событии: обновить стадию + комментарий + задачи
- К сделке прикрепляются ключевые документы (КП, договоры, схемы)

---

#### 2.4. Закрытие сделок

**При закрытии в «Успешно реализовано»:**
- Фиксируется дата запуска
- Фактический объём внедрения
- Финансовый результат

**При закрытии в «Неуспешно»:**
- Обязательно выбирается причина отказа
- Добавляется короткий комментарий

---

#### 2.5. Аналитика и связь лида со сделкой

Для анализа воронки важно сохранять связь между лидами и сделками:

**Схема:**
```
Лид (источник, UTM, объект) → Сделка (воронка продаж, выручка) → Отчёты по каналам и типам объектов
```

**В отчётах смотрим:**
- Количество лидов по каналам
- Конверсию лидов в сделки
- Выручку по каналам
- Сравнение по типам объектов (ЖК / КП / БЦ / Склад)

## Контрольный чек-лист

**При работе с лидом:**
- [ ] Источник лида заполнен (SOURCE_CHANNEL + UTM)
- [ ] Заполнены поля объекта (тип, КПП, оборудование)
- [ ] Установлен ответственный менеджер
- [ ] Все попытки контакта зафиксированы в комментариях
- [ ] При переводе в финальный статус — добавлен комментарий

**При создании сделки:**
- [ ] Сделка связана с Контактом и Компанией
- [ ] Тип объекта указан
- [ ] Стадия соответствует текущему этапу работы
- [ ] Следующий шаг оформлен как задача с датой

---

## Типичные ошибки

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Лид без источника | Не заполнены UTM-поля | Проверить интеграцию форм → Bitrix |
| Дубли лидов | Несколько форм от одного контакта | Использовать деduplication в Bitrix |
| Сделка без связанного объекта | Не создана сущность «Объект» | Создать объект и привязать к сделке |
| Пустые поля ТКП | Не заполнены параметры для КП | Не двигать сделку без заполненных полей |
