# Онлайн-чат: логика работы

## Назначение

Чат-бот на сайте выполняет две задачи:

1. **Квалифицирует новых посетителей** — выявляет потребность и направляет к менеджеру по продажам (заявка или демо)
2. **Принимает обращения существующих клиентов** — собирает описание проблемы и формирует тикет для технического специалиста

Оба сценария завершаются отправкой структурированной карточки в соответствующую admin-панель.

---

## Точка входа — определение пути

Бот не задаёт анкету. Он начинает с одного открытого вопроса и по ответу определяет сценарий.

```
Бот: "Привет! Расскажите, с чем пришли —
      хотите познакомиться с продуктом
      или есть вопрос по работе?"
```

По ответу пользователя бот автоматически классифицирует намерение:

| Сигналы в тексте | Путь |
|---|---|
| "хочу попробовать", "сколько стоит", "расскажите о продукте", "как подключить" | → Сценарий 1: Продажи |
| "не работает", "ошибка", "не могу войти", "сломалось", "баг" | → Сценарий 2: Техподдержка |
| Ответ неоднозначен | → Уточняющий вопрос: "Вы уже используете наш продукт?" |

## Сценарий 1 — Продажи (→ Заявка или Демо)

### Пошаговый путь клиента

```
ШАГ 1. Открытый вопрос о задаче
─────────────────────────────────────────────────────────────
Бот выясняет, что клиент хочет решить.

  Бот:  "Что именно хотите автоматизировать или улучшить?"
  Клиент описывает задачу своими словами.


ШАГ 2. Квалификация (по одному вопросу)
─────────────────────────────────────────────────────────────
Бот задаёт уточняющие вопросы — по одному, как в живом разговоре.
Порядок может меняться в зависимости от ответов.

  → Сроки:   "Когда планируете начать?"
  → Бюджет:  "Есть понимание по бюджету?"
  → ЛПР:     "Вы принимаете решение самостоятельно
               или нужно согласование?"


ШАГ 3. Предложение следующего шага
─────────────────────────────────────────────────────────────
На основе собранной информации бот предлагает конкретное действие.

  Высокая готовность клиента →
    Бот: "Отлично, думаю вам подойдёт демо —
          30 минут, покажем именно под вашу задачу.
          Когда удобно?"

  Низкая готовность или ранняя стадия →
    Бот: "Понял вас. Давайте я передам менеджеру —
          он свяжется и подберёт подходящий вариант."


ШАГ 4. Сбор контакта
─────────────────────────────────────────────────────────────
Бот запрашивает минимально необходимые данные.

  Бот: "Как вас зовут и куда удобнее написать —
        на почту или в телеграм?"

  Собирается: имя + один канал связи (email / телефон / telegram).


ШАГ 5. Подтверждение
─────────────────────────────────────────────────────────────
  Бот: "Отлично, Иван! Передаю менеджеру —
        он напишет вам сегодня."

  Диалог завершается. Карточка уходит в admin-панель менеджера.
```

### Карточка заявки (что получает менеджер)

```
ТИП: Новый лид
───────────────────────────────
Имя:        Иван Петров
Контакт:    @ivan_tg (Telegram)
Задача:     Автоматизация отдела продаж
Бюджет:     до 50 000 руб/мес
Срок:       старт в апреле
ЛПР:        да
Действие:   назначить демо
Время:      пятница после 14:00
───────────────────────────────
Транскрипт диалога: [ссылка]
```

## Сценарий 2 — Техподдержка (→ Тикет → Технический специалист)

### Пошаговый путь клиента

```
ШАГ 1. Описание проблемы
─────────────────────────────────────────────────────────────
Бот просит клиента описать ситуацию своими словами.

  Бот:  "Расскажите подробнее — что происходит
          и когда это началось?"
  Клиент описывает проблему.


ШАГ 2. Сбор технического контекста
─────────────────────────────────────────────────────────────
Бот уточняет данные, необходимые специалисту.
Вопросы задаются по одному, только те, что актуальны.

  → "На каком аккаунте или email вы работаете?"
  → "Это происходит у всех в команде или только у вас?"
  → "Когда впервые заметили — после обновления или раньше?"


ШАГ 3. Попытка авто-решения (если проблема типовая)
─────────────────────────────────────────────────────────────
Если бот распознаёт типовой сценарий — предлагает решение.

  Бот:  "Попробуйте очистить кэш браузера и зайти заново.
          Помогло?"

  Клиент ответил "да"  → диалог закрывается, тикет не создаётся.
  Клиент ответил "нет" → переход к шагу 4.

  Если проблема нетиповая или сложная — шаг 3 пропускается,
  сразу переход к шагу 4.


ШАГ 4. Передача специалисту
─────────────────────────────────────────────────────────────
  Бот: "Понял, передаю техническому специалисту.
         Обычно отвечаем в течение [N] часов.
         Напишем вам на [контакт]."

  Тикет формируется и уходит в admin-панель технического специалиста.
```

### Карточка тикета (что получает технический специалист)

```
ТИП: Тикет техподдержки          ПРИОРИТЕТ: Высокий
───────────────────────────────
Клиент:     ivan@company.ru
Аккаунт:    acc_4821
Проблема:   Не загружается дашборд после обновления
Охват:      только у этого пользователя
Началось:   после обновления 18 марта
Авторешение: предложено / не помогло
───────────────────────────────
Транскрипт диалога: [ссылка]
```

## Уведомления в admin-панелях

**Менеджер по продажам** получает push-уведомление:

```
🔔 Новый лид | Демо
Иван Петров | Telegram: @ivan_tg
Задача: автоматизация продаж
Бюджет: до 50к/мес | Старт: апрель
[Открыть диалог]  [Назначить демо]
```

**Технический специалист** получает push-уведомление:

```
🔴 Новый тикет | Высокий приоритет
ivan@company.ru | acc_4821
Проблема: не загружается дашборд
[Открыть диалог]  [Взять в работу]
```

## Граничные случаи

**Клиент не отвечает на вопрос о контакте**
→ Бот повторяет один раз через другую формулировку. Если снова нет — предлагает оставить email в поле ниже и завершает диалог.

**Клиент груб или офтопит**
→ Бот вежливо возвращает к теме. После двух попыток — предлагает связаться напрямую по телефону/email.

**Путь не определился после двух вопросов**
→ Бот предлагает выбор явно:
```
"Чтобы направить вас к нужному специалисту —
 вы уже используете наш продукт или только рассматриваете?"
```
