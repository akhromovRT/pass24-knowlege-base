## Краткое описание

В новом Битрикс24 помимо стандартных полей (название, сумма, телефон) есть специальные поля, созданные под нашу специфику — продажу PASS24.online. Эта инструкция описывает каждое такое поле: что оно означает, какие значения может принимать, зачем его заполнять и когда. Поля сгруппированы по сущностям: сделка, компания, контакт.

## Пошаговая инструкция

### Шаг 1: Как найти кастомные поля в карточке

**Что делать:**
1. Откройте любую карточку (сделки, компании или контакта).
2. Кастомные поля расположены ниже стандартных полей или в отдельном блоке «Дополнительные поля» / «Пользовательские поля».
3. Если вы не видите поле — нажмите **«Выбрать поле»** (внизу карточки) и добавьте нужное поле в отображение.

**Где:** Карточка сделки / компании / контакта → нижняя часть или блок «Дополнительно».

**Результат:** Вы видите все специальные поля и готовы их заполнять.

## Поля сделки (Deal)

### Шаг 2: Тег сделки

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Тег сделки |
| **Тип** | Выпадающий список (одно значение) |
| **Возможные значения** | СТРАТЕГИЧЕСКИЙ / UPSALE / ПАРТНЁР / *(пусто)* |

**Что означает:**
Специальная метка, определяющая категорию сделки. Влияет на приоритет обработки и отчётность.

| Значение | Когда выбирать |
|----------|---------------|
| **СТРАТЕГИЧЕСКИЙ** | Крупный клиент с высоким потенциалом. Большой объект, крупная сумма, стратегическая важность. Согласуйте с РОП перед установкой |
| **UPSALE** | Клиент уже является действующим — у него есть активный оплаченный договор на PASS24. Вы создаёте новую сделку для допродажи (дополнительный объект, расширение тарифа, оборудование) |
| **ПАРТНЁР** | Клиент пришёл через партнёрский канал (Хиквижн, ЭР-Телеком, Сигур и др.) |
| *(пусто)* | Обычная новая сделка. Большинство сделок будут без тега |

**Зачем заполнять:** РОП видит приоритетные сделки отдельно. Отчёты по партнёрским продажам строятся по этому полю. Стратегические клиенты получают повышенное внимание.

**Когда заполнять:** При создании сделки или сразу после конвертации лида.

### Шаг 3: Тариф

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Тариф |
| **Тип** | Выпадающий список |
| **Возможные значения** | Lite / Standard / Prof / Business / ПАК Lite |

**Что означает:**
Тарифный план, который выбрал клиент.

| Значение | Описание | Для какой воронки |
|----------|----------|------------------|
| **Lite** | Базовый облачный тариф PASS24 — минимальный набор функций | ОБЛАКО |
| **Standard** | Стандартный облачный тариф — основные функции | ОБЛАКО |
| **Prof** | Профессиональный облачный тариф — расширенный функционал | ОБЛАКО |
| **Business** | Бизнес-тариф — полный набор функций, для крупных клиентов | ОБЛАКО |
| **ПАК Lite** | Программно-аппаратный комплекс (единственный тариф для оборудования) | ОБОРУДОВАНИЕ |

**Зачем заполнять:** Тариф определяет стоимость и состав услуги. Нужен для формирования КП, расчёта выручки и аналитики продаж по тарифам.

**Когда заполнять:** На стадии «КП отправлено» — когда вы уже определились с тарифом и подготовили предложение.

### Шаг 4: Период договора

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Период договора |
| **Тип** | Выпадающий список |
| **Возможные значения** | Месяц / Квартал / Год |

**Что означает:**
Расчётный период договора — как часто клиент будет платить.

| Значение | Описание |
|----------|----------|
| **Месяц** | Клиент платит ежемесячно |
| **Квартал** | Клиент платит раз в 3 месяца |
| **Год** | Клиент платит раз в год (обычно со скидкой) |

**Зачем заполнять:** Период влияет на прогнозирование выручки и планирование продлений. Годовой договор — приоритетная цель.

**Когда заполнять:** На стадии «Согласование» или «Договор и оплата», когда условия согласованы с клиентом.

### Шаг 5: URL объекта / ID объекта

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | URL объекта / ID объекта |
| **Тип** | Текстовое поле |
| **Возможные значения** | Ссылка на объект в системе PASS24 / Номер объекта |

**Что означает:**
Уникальный идентификатор объекта клиента в системе PASS24.online. Сейчас это URL-ссылка, в будущем будет заменён на числовой ID.

**Пример:** `https://pass24.online/objects/12345` или `12345`

**Зачем заполнять:** Связывает сделку с конкретным объектом в системе PASS24. Нужно для технической поддержки и отдела сопровождения.

**Когда заполнять:** На стадии «Пилот» (ОБЛАКО) или «Оплата и поставка» (ОБОРУДОВАНИЕ) — когда объект создан в системе.

### Шаг 6: Нестандартное решение

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Нестандартное решение |
| **Тип** | Галочка (да/нет) |
| **Возможные значения** | Включено (да) / Выключено (нет) |

**Что означает:**
Сделка требует индивидуальной технической проработки и участия пресейл-инженера. Это не типовой продукт «из коробки».

**Когда ставить галочку:**
- У клиента нестандартный объект (необычная планировка, специфические требования)
- Нужна интеграция с системами клиента
- Требуется доработка под конкретные задачи
- Масштаб объекта требует инженерного расчёта

**Зачем заполнять:** Если галочка установлена — к сделке подключается пресейл-инженер для технической проработки. Без этого флага инженер не знает, что нужна его помощь.

**Когда заполнять:** На стадии «Квалификация» или «Аудит объекта» — как только стало понятно, что решение нетиповое.

### Шаг 7: Адрес объекта (в сделке)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Адрес объекта |
| **Тип** | Текстовое поле |
| **Возможные значения** | Фактический адрес объекта клиента |

**Что означает:**
Физический адрес объекта, на котором будет установлено оборудование или подключён сервис PASS24.

**Пример:** г. Москва, ул. Ленина, д. 15, ЖК «Парковый»

**Зачем заполнять:** Адрес нужен для выезда на аудит, доставки оборудования, монтажа.

**Важно:** Если у компании **один объект** — адрес заполняется и в карточке компании, и в сделке. Если у компании **несколько объектов** (multi-объект) — адрес каждого объекта хранится в своей сделке, а в компании стоит флаг «Несколько объектов».

**Когда заполнять:** На стадии «Квалификация» — как только клиент назвал адрес.

**Когда заполнять:** На стадии «Договор и оплата» (ОБЛАКО) или «Договор» (ОБОРУДОВАНИЕ) — в момент подписания.

## Поля компании (Company)

### Шаг 10: Балл «теплоты» клиента (Warmth Score)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Балл «теплоты» |
| **Тип** | Число (0-100) |
| **Возможные значения** | От 0 до 100 |

**Что означает:**
Автоматически рассчитанный балл, показывающий, насколько «горячий» клиент — то есть насколько вероятна продажа и насколько активен клиент. Чем выше балл — тем больше шансов на сделку.

**Шкала:**

| Диапазон | Категория | Что это значит для вас |
|----------|-----------|----------------------|
| **70-100** | Горячий | Высокая вероятность продажи. Клиент активен, платит, заинтересован. Работайте с ним в первую очередь |
| **40-69** | Тёплый | Есть интерес, но нужна дополнительная работа. Стоит проявить инициативу, предложить демо или встречу |
| **10-39** | Холодный | Низкая активность. Клиент давно не выходил на связь или показал слабый интерес. Нужно «разогревать» |
| **0-9** | Мёртвый | Клиент не активен, не платит, не выходит на связь. Скорее всего, работа не приведёт к результату |

**Зачем знать:** Помогает расставить приоритеты — кому звонить первому. Горячие клиенты требуют внимания прямо сейчас, холодные можно отложить.

> **Внимание:** Балл рассчитывается автоматически на основе истории оплат, активности и других факторов. Менеджер **не редактирует** это поле вручную. Если считаете, что балл неверный — сообщите администратору.

| Параметр | Значение |

**Зачем заполнять:** Заполняется автоматически. Используйте для быстрого поиска приоритетных клиентов.

### Шаг 12: Сумма оплат (Total Paid)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Сумма оплат |
| **Тип** | Число (рубли) |
| **Возможные значения** | Сумма в рублях |

**Что означает:**
Общая сумма, которую клиент уже заплатил за всё время работы. Данные взяты из бухгалтерской системы 1С.

**Пример:** 450 000 руб. — клиент за 2 года заплатил 450 тысяч рублей.

**Зачем знать:** Понимаете масштаб клиента. Клиент, который заплатил 2 млн рублей, и клиент, который заплатил 10 тысяч — это разные уровни внимания и подхода.

> **Внимание:** Поле заполняется автоматически из данных 1С. Менеджер **не редактирует** его вручную.

| Параметр | Значение |

| **Название в карточке** | Текущий долг |
| **Тип** | Число (рубли) |

### Шаг 14: Несколько объектов (Multi-объект)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Несколько объектов |
| **Тип** | Галочка (да/нет) |
| **Возможные значения** | Включено (да) / Выключено (нет) |

**Что означает:**
У компании больше одного объекта, на котором используется PASS24 (или планируется использование).

**Пример:** Управляющая компания обслуживает 5 жилых комплексов — у неё 5 объектов.

**Как это влияет на работу:**
- Если флаг **включён** — адрес каждого объекта хранится в **своей сделке** (а не в карточке компании).
- Если флаг **выключен** (один объект) — адрес объекта указан в **карточке компании**.

**Зачем заполнять:** Правильная организация данных. Если у компании несколько объектов, а адрес один — будет путаница.

**Когда заполнять:** Когда выясняется, что у клиента больше одного объекта. Обычно на стадии «Квалификация».

### Шаг 15: Адрес объекта (в компании)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Адрес объекта |
| **Тип** | Текстовое поле |
| **Возможные значения** | Фактический адрес размещения оборудования/сервиса |

**Что означает:**
Физический адрес объекта, где установлено (или будет установлено) оборудование PASS24 или подключён облачный сервис.

**Важно:**
- Заполняется в карточке компании, только если у компании **один объект** (флаг «Несколько объектов» выключен).
- Если объектов несколько — адреса хранятся в отдельных сделках.

**Зачем заполнять:** Адрес нужен для логистики, выездов, технической поддержки.

**Когда заполнять:** При создании или обновлении карточки компании, когда известен фактический адрес объекта.

## Поля контакта (Contact)

### Шаг 17: Должность (POST)

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Должность |
| **Тип** | Текстовое поле |
| **Возможные значения** | Любая должность |

**Что означает:**
Должность контактного лица в компании.

**Особое значение:** Если контакт является администратором объекта (техническим представителем на объекте), в поле «Должность» указывается **«Администратор»**. Это специальная роль — администраторы получают доступ к управлению объектом в PASS24.

| Тип контакта | Должность | Роль в продаже |
|-------------|-----------|---------------|
| ЛПР (лицо, принимающее решение) | Генеральный директор, Собственник, Коммерческий директор и т.д. | Принимает решение о покупке |
| Администратор объекта | **Администратор** | Управляет объектом в системе PASS24 после подключения |
| Менеджер / исполнитель | Менеджер, Инженер, Начальник службы безопасности и т.д. | Участвует в процессе, но не принимает финальное решение |

**Зачем заполнять:** Должность помогает понять, с кем вы общаетесь и какие решения этот человек может принимать. Метка «Администратор» нужна для настройки доступа в системе.

**Когда заполнять:** При создании контакта или при конвертации лида.

### Шаг 18: Email контакта — правило одного адреса

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | E-mail |
| **Тип** | Поле email |
| **Возможные значения** | Один email-адрес |

**Что означает:**
Электронная почта контактного лица.

**Важное правило: один email — одно поле.** В поле «E-mail» указывается строго **один** адрес электронной почты. Если у человека несколько email-адресов:
1. Основной (рабочий) email → в поле **E-mail**.
2. Дополнительные email → в поле **Комментарий** к контакту.

**Пример:**
- Поле Email: `ivanov@parkovyy.ru`
- Поле Комментарий: `Дополнительный email: ivanov.petr@gmail.com`

**Зачем это правило:** Один email в поле — это требование для корректной работы рассылок, интеграций и автоматизации. Несколько адресов в одном поле вызывают ошибки.

**Когда заполнять:** При создании контакта.

---

### Шаг 19: Привязка контакта к компании

| Параметр | Значение |
|----------|----------|
| **Название в карточке** | Компания |
| **Тип** | Ссылка на компанию |
| **Возможные значения** | Название компании из CRM |

**Что означает:**
Контакт привязан к конкретной компании. Один человек = одна основная компания.

**Как привязать:**
1. Откройте карточку контакта.
2. Найдите поле **«Компания»**.
3. Начните вводить название компании — система предложит варианты из справочника.
4. Выберите нужную компанию.
5. Сохраните.

**Зачем заполнять:** Без привязки к компании контакт «висит в воздухе» — непонятно, чей это сотрудник. Привязка позволяет видеть всех людей компании в одном месте.

**Когда заполнять:** При создании контакта — всегда привязывайте к компании. Если компании ещё нет в CRM — сначала создайте компанию, затем контакт.

## Контрольный чек-лист

При заполнении карточки сделки проверьте:

- [ ] Тег сделки выбран правильно (или оставлен пустым для обычной сделки)
- [ ] Тариф указан (начиная со стадии «КП отправлено»)
- [ ] Период договора заполнен (начиная со стадии «Согласование»)
- [ ] Адрес объекта заполнен
- [ ] Если решение нетиповое — галочка «Нестандартное решение» установлена
- [ ] При подписании договора — заполнены даты подписания и окончания
- [ ] URL/ID объекта заполнен (для действующих клиентов)

При заполнении карточки компании проверьте:

- [ ] Если у компании один объект — адрес объекта заполнен в карточке компании
- [ ] Если у компании несколько объектов — установлен флаг «Несколько объектов»
- [ ] Проверили автоматические поля: балл теплоты, сумма оплат, долг (не редактировать!)

При заполнении карточки контакта проверьте:

- [ ] Контакт привязан к компании
- [ ] Должность указана (для администратора объекта — «Администратор»)
- [ ] В поле Email указан строго один адрес (дополнительные — в комментарий)

## Типичные ошибки и их решение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Вручную изменил балл «теплоты» | Поле автоматическое | Не редактируйте это поле. Оно рассчитывается автоматически. Если считаете, что балл неверный — сообщите администратору |
| Указал два email через запятую в одном поле | Не знал о правиле одного email | Оставьте в поле Email только один адрес. Второй перенесите в поле «Комментарий» к контакту |
| Не заполнил тариф на стадии «КП отправлено» | Забыл или не определился | Вернитесь в карточку сделки, выберите тариф. Без тарифа невозможно корректно сформировать КП и прогноз |
| Выбрал тариф «ПАК Lite» для сделки в воронке ОБЛАКО | Перепутал воронки | ПАК Lite — только для воронки ОБОРУДОВАНИЕ. Для ОБЛАКО выбирайте: Lite, Standard, Prof или Business |
| Не установил флаг «Несколько объектов» при наличии 3 объектов | Не знал о флаге | Откройте карточку компании → установите галочку «Несколько объектов». Адреса каждого объекта укажите в соответствующих сделках |
| Не указал должность «Администратор» для администратора объекта | Не знал о специальной роли | Откройте карточку контакта → в поле «Должность» напишите «Администратор». Это нужно для корректной настройки доступа в PASS24 |
| Не заполнил даты договора | Забыл при закрытии сделки | Откройте карточку сделки → заполните «Дата подписания» и «Дата окончания». Без этих дат невозможно отслеживать продления |
| Поставил тег UPSALE новому клиенту | UPSALE только для действующих клиентов | Уберите тег. UPSALE означает, что у клиента **уже есть** активный оплаченный договор |
