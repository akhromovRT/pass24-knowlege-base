## Краткое описание

Карта всех инструкций для пользователей нового CRM Битрикс24 (pass24pro.bitrix24.ru), сгруппированных по ролям. Покрывает полный цикл продаж: от получения лида до передачи клиента в отдел сопровождения со статусом «Постоянный клиент». Обновляется по мере завершения этапов миграции.

### Блок 3: Ведение сделки по воронке

#### Воронка ОБЛАКО (9 стадий)

> Новая → Квалификация → Демо/Презентация → КП отправлено → Согласование → Пилот → Договор и оплата → Успех / Провал

| # | Инструкция | Статус | Этап миграции |
|---|-----------|--------|---------------|
| 3.1 | **МПП — Воронка ОБЛАКО: стадии и обязательные действия** | ✅ Готово | Настройка воронок |
| | Пошагово по каждой стадии: **Новая** — первичный контакт, заполнить название сделки, сумму, источник, привязать компанию+контакт. **Квалификация** — BANT (бюджет, ЛПР, потребность, сроки), заполнить тип объекта (КП/ЖК/БЦ/ТЦ), адрес объекта. **Демо/Презентация** — провести демонстрацию PASS24.online, зафиксировать результат. **КП отправлено** — сформировать и отправить КП, добавить товарные позиции, выбрать тариф (Lite/Standard/Prof/Business). **Согласование** — переговоры, корректировка условий; **обязательно заполнить**: тип согласования (Стандартное / Собрание собственников / Тендер / Бюджетный цикл / Смена ЛПР) и ожидаемую дату решения. **Пилот** — развернуть пробную версию, URL объекта. **Договор и оплата** — подписание договора, заполнить дату подписания/окончания, период (месяц/квартал/год), зафиксировать оплату. **Успех** — закрытие. **Провал** — обязательно заполнить причину отказа. | | |

| # | Инструкция | Статус | Этап миграции |
|---|-----------|--------|---------------|
| 3.2 | **МПП — Воронка ОБОРУДОВАНИЕ: стадии и обязательные действия** | ✅ Готово | Настройка воронок |
| | Пошагово: **Новая** — первичный контакт. **Квалификация** — BANT + тип объекта, масштаб, наличие поста охраны/шлагбаума. **Аудит объекта** — выезд или удалённый аудит, формирование ТЗ, если нестандартное решение — поставить флаг `Нестандартное решение` (пресейл + техпроработка). **КП отправлено** — техническое + коммерческое предложение, добавить товарные позиции (тариф: ПАК Lite). **Согласование** — переговоры, корректировка спецификации; **обязательно заполнить**: тип согласования и ожидаемую дату решения. **Договор** — подготовка и подписание, заполнить номер, дата подписания/окончания. **Оплата и поставка** — оплата, поставка оборудования, монтаж. **Успех / Провал** — аналогично ОБЛАКО. | | |

|---|-----------|--------|---------------|
| 3.4 | **МПП — Как заполнять карточку сделки** | ✅ Готово | Настройка воронок |

Кастомные поля сделки: **тариф** (ОБЛАКО: Lite/Standard/Prof/Business; ОБОРУДОВАНИЕ: ПАК Lite), **тип объекта** (КП/ЖК/БЦ/ТЦ/промзона и др.), **адрес объекта** (для multi-объектных компаний — адрес конкретного объекта), **период договора** (месяц/квартал/год), **URL объекта** (для действующих клиентов — ссылка на объект в системе PASS24), **ID объекта** (заменит URL в будущем), **дата подписания/окончания договора**, **нестандартное решение** (если требуется пресейл и техпроработка). Тег сделки: когда и какой ставить. | | |

| | Как добавить товарные позиции (productrows): выбор из каталога, количество, цена за единицу, скидка, НДС. Связь суммы товаров и суммы сделки. Типовые наборы товаров для ОБЛАКО и ОБОРУДОВАНИЕ. | | |
| 3.6 | **МПП — Теги сделок: СТРАТЕГИЧЕСКИЙ, UPSALE, ПАРТНЁР** | ✅ Готово | Настройка тегов |
| | **СТРАТЕГИЧЕСКИЙ** — крупные/стратегические клиенты, повышенный приоритет и внимание РОП. **UPSALE** — действующие клиенты с активным договором, допродажа дополнительных услуг/оборудования; только на активных сделках. **ПАРТНЁР** — сделки через партнёрский канал (Хиквижн, ЭР-Телеком, Сигур и др.), особые условия. Пустой тег — обычная новая сделка. Тег влияет на приоритет обработки и отчётность. Как ставить тег при конвертации лида и при создании сделки вручную. | | |
| 3.7 | **МПП — Стадия «Согласование»: тип и дата решения** | 📋 Запланировано | Настройка воронок |
| | При переводе сделки на стадию «Согласование» **обязательно** заполнить два поля: (1) **Тип согласования** — определяет приоритет: **Стандартное** (высокий приоритет, клиент принимает решение сам за 2–4 недели — активно пушить), **Собрание собственников** (низкий, ждём ОСС — может быть раз в квартал/год), **Тендер / конкурс** (низкий, формальная процедура), **Бюджетный цикл** (средний, ждём нового бюджетного периода), **Смена ЛПР / реорганизация** (низкий, контактное лицо сменилось). (2) **Ожидаемая дата решения** — когда клиент примет решение. Позволяет планировать follow-up. Робот напомнит, если дата прошла. Стандартные сделки без активности >30 дней → уведомление руководителю. Фильтр в канбане по типу согласования помогает расставить приоритеты: сначала «Стандартное», остальное — по дате решения. | | |

Заполнить: номер договора, дата подписания (`UF_CRM_CONTRACT_SIGN_DATE`), дата окончания (`UF_CRM_CONTRACT_END_DATE`), период (`UF_CRM_CONTRACT_PERIOD` — месяц/квартал/год). Прикрепить скан подписанного договора к сделке. | | |
| 5.4 | **МПП — Выставление счёта и контроль оплаты** | ⏸️ Отложено | Настройка документов |
| | Создание счёта из сделки. Отслеживание статуса оплаты. Для ОБОРУДОВАНИЕ: стадия «Оплата и поставка» (PAYMENT) — зафиксировать факт оплаты, статус поставки и монтажа. Для ОБЛАКО: оплата фиксируется на стадии «Договор и оплата» (CLOSING). При задержке — запланировать напоминание, зафиксировать в комментарии. | | |
| 5.5 | **МПП — Закрытие проигранной сделки** | ✅ Готово | Настройка воронок |
| | Перевод на стадию «Сделка провалена» (LOSE). **Обязательно** заполнить причину отказа: для ОБЛАКО — поле «Причины провала PASS24» (цена, конкурент, не нужно, отложили и т.д.), для ОБОРУДОВАНИЕ — поле «Причина провала оборудование». Зачем это важно: аналитика причин отказов влияет на продуктовые решения и стратегию. Не удалять проигранные сделки. | | |

## Роль: Руководитель отдела продаж (РОП)

> Контролирует работу менеджеров, анализирует воронку, управляет распределением клиентов.
> Текущий состав ОП: 5 менеджеров + РОП (Хромов / определяется).

| # | Инструкция | Статус | Этап миграции |
|---|-----------|--------|---------------|
| 8.1 | **РОП — Контроль воронки продаж** | ⏸️ Отложено | Настройка аналитики |
| | Просмотр воронки всего отдела (без фильтра по ответственному). Фильтрация по менеджерам (Крылов, Мельников, Данилов, Корнилов, Филин). Выявление «зависших» сделок — фильтр по типу согласования: «Стандартное» на NEGOTIATION >30 дней → требует вмешательства; «Собрание собственников» / «Тендер» — контроль по ожидаемой дате решения. На PROPOSAL >14 дней. Оценка по тегам: приоритет СТРАТЕГИЧЕСКИЙ и UPSALE. | | |
| 8.2 | **РОП — Перераспределение клиентов и сделок** | ⏸️ Отложено | Настройка прав |
| | Как назначить другого ответственного менеджера (ASSIGNED_BY_ID). Массовое перераспределение через групповые действия. Правила: при увольнении менеджера сделки распределяются между Крыловым и Мельниковым (аналогично миграции). При перегрузке — перевод конкретных сделок. | | |
| 8.3 | **РОП — Отчёты и аналитика CRM** | ⏸️ Отложено | Настройка аналитики |
| | Стандартные отчёты: воронка продаж, конверсия по стадиям, причины отказов, план/факт. Фильтры по воронкам (ОБЛАКО/ОБОРУДОВАНИЕ/РЕКЛАМА), по менеджерам, по периоду. Экспорт данных. Дашборды. Анализ warmth_score: сколько горячих/тёплых клиентов в работе. | | |
