## Краткое описание

Карточка сделки — это основная рабочая единица менеджера в CRM. В ней хранится вся информация о продаже: от первого контакта до подписания договора и оплаты. Данная инструкция описывает **каждое поле** карточки сделки: что оно означает, когда и как его заполнять. Применимо ко всем трём воронкам.

---

## Как открыть карточку сделки

**Путь:** CRM → Сделки → выберите воронку → нажмите на карточку сделки в канбане или списке.

Карточка сделки содержит:
- **Верхняя часть** — полоска стадий (прогресс-бар), название сделки.
- **Левая колонка** — основные поля и кастомные поля.
- **Правая колонка / нижняя часть** — таймлайн (комментарии, дела, история).
- **Вкладки** — Товары, Документы, Дела и др.

## Пошаговая инструкция

### Раздел 1: Стандартные поля

Эти поля есть в каждой сделке, независимо от воронки.

#### Название сделки

| Параметр | Описание |
|----------|----------|
| **Где:** | Верхняя часть карточки, самое крупное поле |
| **Что писать:** | Краткое понятное описание: что продаём + кому |
| **Когда заполнять:** | При создании сделки |
| **Обязательность:** | Обязательно |

**Формат названия:**

| Воронка | Формат | Пример |
|---------|--------|--------|
| ОБЛАКО | «PASS24 Облако — [Название объекта/компании]» | «PASS24 Облако — ЖК Солнечный» |
| ОБОРУДОВАНИЕ | «ПАК — [Название объекта], [кратко что]» | «ПАК — ЖК Речной, 2 шлагбаума» |
| РЕКЛАМА | «Реклама — [Тип] — [Период/Клиент]» | «Реклама — баннер на PASS24 — апрель 2026» |

#### Сумма и валюта

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «Сумма» в карточке сделки |
| **Что писать:** | Сумма сделки в рублях. Обновляется по мере продвижения |
| **Когда заполнять:** | При создании — предварительная оценка. При отправке КП — точная сумма. При закрытии — финальная сумма по договору |
| **Обязательность:** | Обязательно |
| **Валюта:** | По умолчанию RUB (рубли). Менять не нужно |

> **Совет:** Если добавлены товарные позиции (вкладка «Товары»), сумма может обновляться автоматически. Убедитесь, что финальная сумма совпадает с суммой в договоре.

### Раздел 2: Кастомные поля сделки

Это специальные поля, созданные для PASS24. Они находятся в карточке сделки ниже стандартных полей (или в отдельном блоке, в зависимости от настройки).

---

#### Тариф (UF_CRM_TARIFF)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «Тариф» в карточке сделки |
| **Тип:** | Выпадающий список |
| **Когда заполнять:** | На стадии «КП отправлено» — когда готовите коммерческое предложение |
| **Обязательность:** | Обязательно перед закрытием сделки |

**Варианты по воронкам:**

| Значение | Воронка | Описание |
|----------|---------|----------|
| **Lite** | ОБЛАКО | Базовый тариф — минимальный функционал |
| **Standard** | ОБЛАКО | Расширенный тариф — стандартные потребности |
| **Prof** | ОБЛАКО | Профессиональный — расширенные отчёты, интеграции |
| **Business** | ОБЛАКО | Максимальный — полный функционал, приоритетная поддержка |
| **ПАК Lite** | ОБОРУДОВАНИЕ | Единственный тариф для оборудования |

Для воронки РЕКЛАМА тариф обычно не применяется (оставьте пустым).

---

#### Период договора (UF_CRM_CONTRACT_PERIOD)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «Период договора» |
| **Тип:** | Выпадающий список |
| **Варианты:** | месяц, квартал, год |
| **Когда заполнять:** | На стадии «Договор и оплата» (ОБЛАКО) / «Договор» (ОБОРУДОВАНИЕ) — при подготовке договора |
| **Обязательность:** | Обязательно перед закрытием сделки |

**Что означает:**
- **Месяц** — клиент платит ежемесячно, договор продлевается помесячно.
- **Квартал** — клиент платит раз в квартал.
- **Год** — клиент платит за год вперёд (обычно со скидкой).

Это расчётный период оплаты, а не срок действия договора.

#### URL объекта (UF_CRM_OBJECT_URL)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «URL объекта» |
| **Тип:** | Текстовое поле (ссылка) |
| **Когда заполнять:** | Когда объект клиента зарегистрирован в системе PASS24 — обычно на стадии «Пилот» или при закрытии сделки |
| **Обязательность:** | Обязательно для действующих клиентов (ОБЛАКО). Для ОБОРУДОВАНИЕ — если подключено облачное управление |

**Что это:** Прямая ссылка на объект клиента в системе PASS24.online. Позволяет быстро перейти к объекту из карточки сделки.

**Пример:** `https://app.pass24.online/object/12345`

> **Важно:** В будущем URL будет заменён на ID объекта (поле ниже). Пока заполняйте оба поля, если доступны.

---

#### ID объекта (UF_CRM_OBJECT_ID)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «ID объекта» |
| **Тип:** | Текстовое поле |
| **Когда заполнять:** | Когда объекту присвоен номер в системе PASS24 |
| **Обязательность:** | Рекомендуется (станет обязательным после замены URL) |

**Что это:** Уникальный номер (идентификатор) объекта в системе PASS24. Более надёжный способ идентификации, чем URL.

**Пример:** `12345`

---

#### Нестандартное решение (UF_CRM_CUSTOM_SOLUTION)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «Нестандартное решение» (галочка / чекбокс) |
| **Тип:** | Да / Нет (boolean) |
| **Когда заполнять:** | На стадии «Аудит объекта» (ОБОРУДОВАНИЕ) или при квалификации, если выяснено, что нужно нетиповое решение |
| **Обязательность:** | Обязательно оценить при аудите (ОБОРУДОВАНИЕ). Для ОБЛАКО — при нестандартных требованиях |

**Когда ставить «Да»:**
- Клиенту нужна интеграция с системами, которые не поддерживаются «из коробки».
- Нетипичный объект, требующий индивидуальной проработки.
- Клиент запрашивает функционал, которого нет в стандартной поставке.
- Проект требует участия инженерного отдела на этапе пресейла.

**Что происходит при установке флага:** Сделка получает повышенное внимание со стороны технического отдела и пресейла. РОП видит такие сделки в отчётах как требующие дополнительных ресурсов.

---

#### Адрес объекта (UF_CRM_OBJECT_ADDRESS)

| Параметр | Описание |
|----------|----------|
| **Где:** | Поле «Адрес объекта» |
| **Тип:** | Текстовое поле |
| **Когда заполнять:** | На стадии «Квалификация» — когда выяснили, где находится объект |
| **Обязательность:** | Обязательно для multi-объектных компаний. Рекомендуется для всех |

**Что это:** Фактический адрес объекта, куда устанавливается оборудование или подключается облачный сервис. Особенно важно для компаний с несколькими объектами (multi-объект): у компании может быть один юридический адрес, но несколько объектов в разных местах. В этом случае адрес каждого объекта хранится в своей сделке.

**Пример:** «г. Москва, ул. Ленина, д. 15, ЖК Солнечный»

> **Как узнать, multi-объектная ли компания:** В карточке компании есть поле «Multi-объект» (UF_CRM_MULTI_OBJECT). Если там стоит «Да» — у компании несколько объектов, и в каждой сделке нужно указывать адрес конкретного объекта.

### Раздел 4: Служебные поля (не редактируются менеджером)

Эти поля заполняются автоматически при миграции или системой. Менеджеру не нужно их менять, но полезно знать, что они означают.

| Поле | Описание | Зачем |
|------|----------|-------|
| **ID старой сделки** (UF_CRM_OLD_DEAL_ID) | ID сделки в старом Битрикс24 | Для трассировки миграции — связь между старой и новой сделкой |
| **Старая воронка** (UF_CRM_OLD_PIPELINE) | Название воронки в старом CRM | Показывает, из какой воронки мигрирована сделка |

Если вы видите эти поля заполненными — значит, сделка была перенесена из старого CRM при миграции.

### Раздел 6: Вкладка «Товары»

**Где:** В карточке сделки — вкладка **«Товары»** (или «Товарные позиции»).

**Что это:** Список конкретных товаров и услуг, входящих в сделку.

**Как добавить:**
1. Откройте вкладку «Товары» в карточке сделки.
2. Нажмите **«Добавить товар»**.
3. Выберите товар из каталога или введите вручную.
4. Укажите: количество, цену за единицу, скидку (если есть), НДС.
5. Сумма сделки обновится на основе товарных позиций.

**Типичные наборы:**

| Воронка | Что добавлять |
|---------|--------------|
| ОБЛАКО | Подписка PASS24 (тариф Lite/Standard/Prof/Business), настройка, обучение |
| ОБОРУДОВАНИЕ | Шлагбаумы, считыватели, контроллеры, монтажные работы, пусконаладка |
| РЕКЛАМА | Рекламное размещение (тип, объём, период) |

---

### Раздел 7: Таймлайн и комментарии

**Где:** Правая колонка или нижняя часть карточки сделки.

**Зачем:** Таймлайн — это полная история сделки. Все звонки, письма, комментарии, перемещения по стадиям фиксируются здесь автоматически.

**Правила работы с комментариями:**
1. **После каждого контакта** с клиентом — добавьте комментарий: итог разговора, договорённости, следующий шаг.
2. **Формат комментария:**
   - Дата контакта (если отличается от текущей).
   - С кем общались (ФИО, должность).
   - Итог: что обсудили, что решили.
   - Следующий шаг: что делать дальше и когда.
3. **Упоминание коллеги:** введите `@` и начните набирать имя — коллега получит уведомление. Используйте для привлечения внимания РОП, инженера, пресейла.
4. **Прикрепление файлов:** нажмите скрепку в окне комментария — прикрепите КП, договор, скан, скриншот.

## Контрольный чек-лист

Универсальный чек-лист перед закрытием сделки как **«Успешна»**:

- [ ] **Название** — понятное, по формату
- [ ] **Сумма** — актуальна, совпадает с договором
- [ ] **Компания** — привязана
- [ ] **Контакт** — привязан
- [ ] **Источник** — указан
- [ ] **Тариф** — выбран (Lite/Standard/Prof/Business для ОБЛАКО; ПАК Lite для ОБОРУДОВАНИЕ)
- [ ] **Товарные позиции** — добавлены
- [ ] **Тип объекта** — указан
- [ ] **Адрес объекта** — указан (обязательно для multi-объект)
- [ ] **Дата подписания договора** — заполнена
- [ ] **Дата окончания договора** — заполнена
- [ ] **Период договора** — указан (месяц / квартал / год)
- [ ] **URL или ID объекта** — заполнен (для ОБЛАКО и подключённого ОБОРУДОВАНИЕ)
- [ ] **Нестандартное решение** — флаг установлен (если применимо)
- [ ] **Тег сделки** — установлен (если применимо)
- [ ] **Договор** — скан прикреплён к сделке

## Типичные ошибки и их решение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Сделка без компании и контакта | Создали сделку и забыли привязать | Откройте карточку → привяжите компанию и контакт. Без привязки нет связи с клиентской базой |
| Сумма сделки = 0 при закрытии | Не обновили сумму после КП или переговоров | Обновите сумму. Она должна совпадать с итоговой суммой договора |
| Тариф не выбран | Поле осталось пустым | Выберите тариф на стадии КП или позже. Для ОБЛАКО: Lite/Standard/Prof/Business. Для ОБОРУДОВАНИЕ: ПАК Lite |
| Нет товарных позиций | Не добавили товары во вкладку «Товары» | Добавьте — это влияет на корректность суммы и аналитику |
| Адрес объекта не заполнен для multi-объектной компании | Не знали, что компания multi-объектная | Проверьте карточку компании — поле «Multi-объект». Если «Да» — обязательно укажите адрес в сделке |
| Даты договора не заполнены | Забыли при подписании | Заполните обе даты: подписания и окончания. Они нужны для контроля продлений |
| URL объекта — битая ссылка | Скопировали неправильно или объект удалён | Проверьте ссылку, перейдя по ней. Если не работает — уточните у технической поддержки |
| Причина провала не заполнена | Закрыли сделку без указания причины | Откройте сделку, заполните «Причина отказа» и специфичное поле (PASS24 или оборудование) |
