## Краткое описание

На компьютере руководителя работает программа-наблюдатель, которая **автоматически** обрабатывает банковские выписки. Задача бухгалтера — ежедневно выгружать выписку из 1С и положить файл в определённую папку. Всё остальное система сделает сама:

- Найдёт все входящие платежи от клиентов
- Обновит сводную таблицу поступлений по месяцам
- Рассчитает задолженность и статус каждого клиента
- Запишет отчёт о том, что изменилось

## Пошаговая инструкция

### Шаг 1. Выгрузить выписку из 1С

1. Откройте 1С: Бухгалтерия
2. Перейдите в раздел **Банк и касса → Банковские выписки**
3. Выберите расчётный счёт: **40702 810 0 02630 000347**
4. Установите период: **текущий рабочий день** (или несколько дней, если выписка за выходные)
5. Нажмите **Выгрузить в Excel** (формат `.xlsx`)

**Результат:** На рабочем столе появится файл вида:
```
Выписка_40702810002630000347_17.03.2026.xlsx
```

> **Важно:** Если выписка за несколько дней (например, за выходные), файл будет выглядеть так:
> `Выписка_40702810002630000347_14.03.2026–16.03.2026.xlsx`
> Это нормально, система обработает его так же.

---

### Шаг 2. Положить файл в папку

Скопируйте (или перетащите) файл выписки в папку:

```
Bitrix24-migration / выписка-1с / ежедневные выписки 1с /
```

> **Путь на компьютере руководителя:**
> `~/Library/Mobile Documents/com~apple~CloudDocs/Cursor/@work-projects/Bitrix24-migration/выписка-1с/ежедневные выписки 1с/`

**Результат:** Файл появился в папке. Больше ничего делать не нужно.

---

### Шаг 3. Дождаться обработки (автоматически)

Система-наблюдатель обнаружит новый файл в течение **5-10 секунд** и автоматически:

1. Прочитает все входящие платежи (кредитовые операции)
2. Сопоставит каждый платёж с клиентом по ИНН
3. Обновит сводную таблицу `анализ_поступлений_по_месяцам.xlsx`
4. Пересчитает итоги, тренды и статусы задолженности
5. Запишет отчёт об изменениях в `changelog_payments.xlsx`
6. Переместит обработанный файл в подпапку `.processed`

**Как понять, что обработка завершена:**
- Файл **исчез** из папки `ежедневные выписки 1с` — значит, обработан
- Файл **появился** в подпапке `.processed` — подтверждение обработки

После выгрузки и размещения файла проверьте:

- [ ] Файл имеет расширение `.xlsx` (не `.xls`, не `.csv`)
- [ ] Имя файла начинается с `Выписка_40702810002630000347_`

## Типичные ошибки

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Файл остаётся в папке и не обрабатывается | Имя файла не начинается с `Выписка_` или расширение не `.xlsx` | Проверить имя файла. Переименовать если нужно |
| Файл остаётся в папке | Программа-наблюдатель не запущена | Сообщить администратору (Алексей Хромов) |
| Файл обработан, но сумма не совпадает | В выписке есть дебетовые операции (они не учитываются — только входящие платежи) | Это нормально: считаются только кредитовые (входящие) операции |
| Клиент не найден в таблице | Новый клиент, которого ещё не было в базе | Система автоматически добавит его. В changelog будет запись «Новая компания» |
| Повторная обработка файла | Файл скопирован обратно из `.processed` | Система проверяет хеш файла — если файл не изменился, повторной обработки не будет |

## FAQ

**Что если я пропустила день и не выгрузила выписку?**
Ничего страшного. Выгрузите выписку за пропущенные дни одним файлом (укажите диапазон дат при выгрузке из 1С). Система обработает его корректно — даты берутся из содержимого файла, а не из его названия.

**Что если я положу файл не за тот счёт?**
Система обработает только файлы, имя которых начинается с `Выписка_40702810002630000347_`. Файлы с другим номером счёта будут проигнорированы.

**Можно ли положить сразу несколько файлов?**
Да. Система обработает их по порядку — от более ранней даты к более поздней.

**Что если я случайно положу один и тот же файл дважды?**
Система запоминает каждый обработанный файл (по имени и содержимому). Повторный файл будет пропущен.

**Что если нужно исправить выписку?**
Если бухгалтер выгрузил выписку с ошибкой и затем положит исправленный файл с тем же именем — система обнаружит, что содержимое изменилось, и обработает его заново.

**Где посмотреть лог работы системы?**
Файл лога: `~/Library/Logs/payments-watcher.log` на компьютере руководителя. Там видно время обработки каждого файла и количество транзакций.

**Что если файл задолженности обновился?**
Файл `Задолженность покупателей...xls` в папке `выписка-1с/входящие/` используется для расчёта колонок «Факт. долг» и «Просроч. долг». Когда бухгалтер обновляет этот файл, система автоматически подтянет новые данные при следующей обработке выписки.

## Что делает система «под капотом»

### Общая схема

```
Бухгалтер               Система-наблюдатель            Результат
─────────               ─────────────────────          ─────────

Выгрузка из 1С    ──►   Обнаружение файла
                        (5-10 сек)
                             │
                             ▼
                        Парсинг выписки
                        (только кредит > 0)
                             │
                             ▼
                        Сопоставление по ИНН ──►  анализ_поступлений
                        (или по названию)         _по_месяцам.xlsx
                             │                    (обновлён)
                             ▼
                        Пересчёт итогов,     ──►  changelog_payments.xlsx
                        трендов, статусов         (новый лист за день)
                             │
                             ▼
                        Файл → .processed
```

### Какие данные извлекаются из выписки

Из каждой строки выписки система берёт:
- **Дату** операции — определяет, в какой месяц попадёт платёж
- **Сумму кредита** — только входящие платежи (исходящие игнорируются)
- **ИНН контрагента** — по нему ищется клиент в сводной таблице
- **Название контрагента** — используется если ИНН не указан

### Как рассчитывается тренд

| Тренд | Что значит |
|-------|-----------|
| `+15%` | Клиент платит больше, чем в среднем за весь период (среднее за последние 3 мес. выше общего среднего на 15%) |
| `-20%` | Клиент платит меньше обычного (спад на 20%) |
| `+0%` | Стабильные платежи, без изменений |
| `УШЁЛ` | Клиент не платил последние 3 полных месяца |
| `НОВЫЙ` | Первый платёж клиента поступил в текущем месяце |

### Как определяется статус задолженности

| Статус | Условие |
|--------|---------|
| `ОК` | Клиент заплатил в текущем месяце не менее 80% от своего среднего платежа |
| `РИСК` | Клиент пока не заплатил в этом месяце, но обычно платит стабильно (платил не менее 6 из последних 12 месяцев) |
| `ДОЛГ` | Клиент не заплатил + есть фактическая задолженность в 1С, или пропущено 2 и более месяцев подряд |

### Как обновляется сегментация

Клиенты группируются по общей сумме поступлений:

| Сегмент | Порог |
|---------|-------|
| Крупные | Более 500 000 руб. |
| Средние | 100 000 — 500 000 руб. |
| Малые | 30 000 — 100 000 руб. |
| Микро | Менее 30 000 руб. |
