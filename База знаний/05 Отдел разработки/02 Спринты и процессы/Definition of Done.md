## Краткое описание

Definition of Done (DoD) — набор критериев, при выполнении которых задача считается завершённой и готовой к сдаче. Обеспечивает единый стандарт качества и прозрачность приёмки.

---

## Основной контент

### Общие критерии DoD (базовый шаблон)

Задача считается выполненной, когда выполнены **все** пункты:

| № | Критерий | Проверка |
|---|----------|----------|
| 1 | **Код написан** | Реализация соответствует описанию задачи |
| 2 | **Code review пройден** | Одобрение от назначенного ревьюера |
| 3 | **Тесты пройдены** | Существующие тесты зелёные, при необходимости добавлены новые |
| 4 | **Нет критичных замечаний линтера** | Линтер не выдаёт ошибок |
| 5 | **Документация обновлена** | README, API, комментарии — при необходимости |
| 6 | **Приёмка продуктом** | Продукт/заказчик подтвердил соответствие критериям приёмки |

---

### Специфичные критерии (по типу задачи)

| Тип задачи | Дополнительные критерии |
|------------|-------------------------|
| **Фича** | Критерии приёмки из задачи выполнены, UX проверен |
| **Баг** | Воспроизведение исправлено, регрессия не внесена |
| **Рефакторинг** | Поведение не изменилось (где применимо), покрытие тестами сохранено |
| **MVP / гипотеза** | Минимальный объём для теста готов, можно включать в эксперимент |

---

### Исключения

- **Горячие фиксы** — можно сократить DoD (код + базовые тесты + деплой), с последующим восполнением документации и ревью
- **Эксперименты / прототипы** — DoD может быть упрощён по согласованию с продуктом

---

## Контрольный чек-лист при приёмке

- [ ] Код ревью пройдено
- [ ] Тесты зелёные
- [ ] Критерии приёмки из задачи выполнены
- [ ] Документация обновлена (если требуется)
- [ ] Продукт подтвердил приёмку
