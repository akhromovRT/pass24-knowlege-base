## Краткое описание

Данный документ содержит структурированное обучение по веб-интерфейсу PASS24.online на основе записи встречи от 18.11.2025 для объекта Кандерсон (номер объекта 2192). В документе рассмотрены все основные модули системы, включая относительно новые — «Группы адресов» и «Баланс + Правила». Особенность обучения — акцент на безопасности: контроль передачи учётных данных, лимиты пропусков на пользователя, запрет самостоятельного присоединения к объекту, управление просроченными пропусками. Подробно задокументированы известные проблемы на Android (push-уведомления, тема запроса).

### Настройки объекта — Номер телефона

**Назначение:** Номер телефона администратора отображается у пользователей в мобильном приложении как «горячая линия» для экстренной связи.

#### Изменение или скрытие номера

**Что делать:**
1. Перейдите в модуль **«Объект»**
2. Нажмите **«Изменить»**
3. Скорректируйте номер телефона

**Где:** Модуль «Объект» → кнопка «Изменить»

**Результат:** Новый номер отображается у пользователей в приложении

**Важно:**
- Номер телефона — обязательное поле, убрать его нельзя
- Если не хотите показывать реальный номер — замените на «липовый» (нули или девятки): система не сломается
- Номер присваивается к учётной записи администратора при создании системы

### Модуль Сотрудники

**Назначение:** Сотрудники — это администраторы системы, управляющие настройками, пользователями и адресами. Главный администратор имеет полные права; остальным сотрудникам можно ограничить функционал.

#### Создание сотрудника

**Что делать:**
1. Нажмите кнопку **«Новый сотрудник»** (или «Добавить»)
2. Заполните: ФИО, email, пароль
3. В поле **«Группа»** выберите нужное подразделение (Администраторы, Охрана, Операторы)
4. Нажмите **«Сохранить»**

**Где:** Раздел «Сотрудники»

**Результат:** Сотрудник добавлен; авторизация — через браузер по email и паролю

**Важно:**
- Номер телефона при создании сотрудника необязателен
- Авторизация сотрудников — **только через браузер** (не мобильное приложение)
- Если email выдуманный — восстановить пароль будет невозможно

#### Восстановление пароля сотрудника

Два варианта:
1. **Администратор:** три точки → «Редактировать» → значок карандаша → задать новый пароль
2. **Сам сотрудник:** на странице входа нажать «Забыли пароль» → письмо на email с инструкцией

#### Редактирование прав сотрудника

**Способ 1 — индивидуально:**
1. Напротив нужного сотрудника нажмите **три точки** → **«Редактировать права»**
2. Пройдитесь по модулям и выставьте разрешения (создание, редактирование, удаление и т.д.)
3. Нажмите **«Сохранить»**

**Способ 2 — через подгруппу:**
1. Перейдите в раздел **«Права»**
2. Создайте или откройте нужную подгруппу (например, «Охрана», «Операторы»)
3. Настройте права для подгруппы
4. Перетащите сотрудника в нужную подгруппу (или через «три точки» → «Редактировать» → выбрать группу)

**Результат:** Сотрудник автоматически принимает права подгруппы

**Важно:**
- Если новая подгруппа не отображается при создании сотрудника — обновите страницу

### Модуль Пользователи

**Назначение:** Пользователи — это жители/собственники, работающие только через мобильное приложение. Они могут заказывать пропуска и оформлять доверенности.

#### Три способа добавить пользователя

**Способ 1 — вручную:**
1. Нажмите **«Добавить»**
2. Заполните: ФИО, номер телефона (+7...), email (необязательно), описание (внутренняя пометка)
3. Выберите **группу** пользователя (внутренняя классификация, на доступ не влияет)
4. Привяжите к **адресу** (обязательно)
5. Нажмите **«Сохранить»**

**Способ 2 — через запрос пользователя:**
- Пользователь регистрируется в приложении и вводит номер объекта (2192)
- Запрос поступает в раздел «Запросы» → администратор одобряет или отклоняет

**Способ 3 — массовая загрузка через Excel:**
1. Раздел «Адреса» → значок облака → «Импорт»
2. Выбрать **«Пример с пользователями»** → скачать шаблон
3. Заполнить: город, улица, дом (обязательно), корпус/строение (необязательно), номер телефона, ФИО
4. Загрузить файл → адреса и пользователи добавятся одновременно

**Важно:**
- Номер телефона — через +7 (или 7) — **главный идентификатор** пользователя
- Пользователь без адреса существовать в системе не может
- Группы пользователей — только внутренняя метка, на права не влияют
- **Для Кандерсон**: самостоятельное присоединение через приложение **отключено** — всех пользователей добавляет только администратор вручную

#### Отслеживание регистрации пользователей

Через **шестеренку** в модуле «Пользователи» добавьте поле «Зарегистрирован» — будет видно, зашёл ли пользователь хотя бы раз в приложение под своим номером.

### Модуль Адреса

**Назначение:** Управление адресами объекта — добавление, редактирование, блокировка.

#### Добавление адреса

**Что делать:**
1. Нажмите **«Добавить»**
2. Выберите объект (Кандерсон)
3. Заполните: улица (обязательно), дом (обязательно), корпус/строение/офис (необязательно), короткое название (внутренняя пометка)
4. Нажмите **«Сохранить»**

**Где:** Раздел «Адреса»

**Важно:**
- Короткое название — внутренняя пометка, пользователи в приложении её не видят
- Настройка отображаемых полей — через **шестеренку**

#### Блокировка адреса

**Что делать:**
1. Найдите адрес в списке
2. Нажмите **три точки** → **«Редактировать»**
3. Включите **«Блокировка адреса»** (блокирует весь адрес) или нажмите **замочек** напротив конкретного пользователя (блокирует только его на этом адресе)

**Важно:**
- У адреса **нет отдельной кнопки «Заблокировать»** в списке — только через редактирование
- У пользователя кнопка «Заблокировать» есть прямо в списке (наверху)

### Модуль Пропуска

**Назначение:** Основной рабочий модуль. Здесь охранники видят все пропуска (действующие и закрытые) и управляют въездом/выездом.

#### Хранение пропусков

- В **видимом доступе** пропуска хранятся ~30 дней
- Потом уходят в архив (но данные не теряются)
- Чем активнее закрываются пропуска — тем быстрее старые уходят в архив
- Глубокая история (более 31 дня) — через запрос в техподдержку

#### Создание пропуска

**Что делать:**
1. Нажмите **«Новый пропуск»**
2. Выберите адрес и пользователя на этом адресе
3. Выберите тип: разовый / временный / постоянный
4. Для разового и временного — укажите временной интервал
5. Заполните данные (ФИО или номер авто)
6. При необходимости нажмите **«Добавить гостя»** для групповых пропусков
7. Нажмите **«Сохранить»**

**Альтернатива для группы:** загрузка через Excel (строчки сверху вниз: ФИО, данные авто)

**Важно:** Не создавайте более 40–50 пропусков за раз — нагрузка на систему, возможны подвисания

#### Типы пропусков и их логика

| Тип | Закрытие |
|-----|----------|
| **Разовый** | После события «приехал-уехал»; если не выехал — по окончании времени |
| **Временный** | По истечении срока действия (в интервале можно бесконечно въезжать/выезжать) |
| **Постоянный** | Вручную или пользователем; сначала смените статус на «вне территории» |

**Важно:** Пропуск со статусом **«на территории» закрыть нельзя** — сначала нажмите «Гость уехал»

#### Настройка поведения просроченных пропусков

В модуле «Объект» → раздел «Настройки» выбирается одно из трёх действий при истечении срока:

1. **Висит в просроченных** до смены статуса на «вне территории» → потом автоматически закрывается
2. **Продлевается на час** до смены статуса → потом закрывается
3. **Принудительно закрывается** сразу

**Рекомендация:** Вариант «продлевается на час» — **не выбирайте**: просроченные пропуска будут накапливаться и тормозить систему (реальный пример — 320 тысяч просроченных пропусков с 2022 года у одного клиента).

**Для Кандерсон:** Выбран вариант «висит в просроченных» — это позволяет зафиксировать реальное время выезда и видеть просрочку.

#### Массовое закрытие пропусков

1. Отфильтруйте пропуска (по пользователю, адресу, типу)
2. Включите **режим массового закрытия**
3. Поставьте галочку **«Выбрать все найденные»**
4. Нажмите **«Закрыть»**

#### Экспорт событий пропусков

**Где:** Модуль «Пропуска» → значок облака со стрелкой → «Экспортировать события пропусков»

- Период: **максимум 31 день** от текущей даты
- Можно фильтровать по адресу, пользователю, типу
- Отчёт приходит на email авторизованного пользователя
- Содержит: кто создал, номер пропуска, тип, адрес, дату/время въезда-выезда, инициатор события

Для более глубокого архива — запрос в техподдержку (формат отчёта идентичный).

### Модуль Запросы

**Назначение:** Обработка входящих запросов от пользователей и управление настройками запросов.

#### Типы запросов

| Тип | Описание |
|-----|----------|
| **Присоединение к объекту** | Пользователь хочет присоединиться к объекту (для Кандерсон — отключено) |
| **Запрос на пропуск** | Разовые и временные — могут попадать автоматически; постоянные — **только через запросы** |
| **Сообщение (переписка)** | Пользователь хочет написать администратору |
| **Доверенность** | Запрос на одобрение доверенности |

**Важно:**
- Постоянный пропуск — **всегда через запросы**, это нельзя изменить
- Внутренний комментарий при отклонении виден пользователю

#### Настройки модуля запросов (в разделе «Объект»)

- **Запросы на присоединение** — для Кандерсон отключены (только ручное добавление администратором)
- **Запросы на постоянный пропуск** — отключены (документы только на бумаге)
- **Создание доверенности** — через запрос или автоматически (на усмотрение)

### Модуль Доверенности

**Назначение:** Временный полный доступ в систему для другого лица (арендатор, временный жилец). Доверенное лицо может самостоятельно создавать пропуска.

#### Создание доверенности

**Что делать:**
1. Перейдите в раздел **«Доверенности»**
2. Выберите **пользователя** (арендодатель — кто даёт доверенность)
3. Выберите **адрес**
4. Укажите **период активности**: дата с (можно указать точное время часы:минуты) — дата по
5. Введите **номер телефона** доверенного лица
6. Нажмите **«Сохранить»**

**Где:** Раздел «Доверенности»

**Результат:** Доверенное лицо создаётся как пользователь в системе на указанный период

**Важно:**
- Можно указать **точное время начала** (часы:минуты) — доверенность станет активной именно в это время
- **Редактировать доверенность нельзя** — только создавать новую
- **Продлить доверенность нельзя** — только создать новую (это сделано умышленно для безопасности)
- При закрытии/истечении доверенности: пользователь **удаляется** из системы, все его пропуска **закрываются**

#### Данные удалённого пользователя в отчётах

Если пользователь (в том числе по доверенности) был удалён из системы — **его данные сохраняются в отчётах** за период, когда он был в системе. Экспорт отчёта за тот период покажет все его пропуска и события.

### Модуль Объект — Настройки

**Назначение:** Центральный раздел настроек системы. Управление лимитами, разрешениями, опциями, чёрным списком, КПП, балансом, группами адресов.

**Важно:** В каждом разделе настроек после изменений обязательно нажимайте **«Применить»**.

#### Лимит активных пропусков на пользователя

**Назначение:** Ограничение количества разовых пропусков, которые один пользователь может иметь одновременно.

**Как работает:**
- Если лимит = 1: пользователь **не сможет создать новый разовый пропуск**, пока не закроет предыдущий
- Лимит задаётся отдельно для разных типов транспорта (разовый автомобильный, пешеходный и т.д.)

**Важно:** Лимит применяется **на одного пользователя**, не на всю систему. Таким образом можно регулировать поток гостей и предотвращать злоупотребления.

#### Разрешения для создания пропусков

Для каждого типа пропуска можно выбрать: **Разрешено** / **Запрещено** / **По запросу**

Настройка «По запросу» означает: пропуск не активируется сразу, а попадает в раздел «Запросы» для дополнительного одобрения.

**Для Кандерсон:**
- Создание временных пешеходных пропусков для пользователей — **запрещено**
- Максимальный срок действия разового пропуска — **2 часа**

#### Марка и формат номера автомобиля

- **Марка обязательна** (да/нет) — если «да», поле обязательно при создании пропуска
- **Формат номера** — настройка валидации (можно разрешить произвольный формат или только стандартный)

#### Опции объекта (такси, доставка и т.д.)

- Опции — дополнительная информация о цели визита (такси, доставка, строители, осмотр...)
- Можно оставить только нужные, убрав лишние в «неактивные»
- Если убрать все — при заказе пропуска поле выбора опции не будет отображаться

#### Минуты (специальный модуль)

**Назначение:** Ограничение времени нахождения на территории для каждой опции (такси, доставка...).

**Как работает:**
- Задаётся допустимое время нахождения в минутах для каждой опции
- При превышении лимита — уведомление в колокольчик администратора
- Это **отдельный платный модуль**, разработанный под конкретного клиента

**Для Кандерсон:** Не используется.

#### Черный список

**Назначение:** Запрет создания пропусков на конкретный номер автомобиля.

**Что делать:**
1. Раздел «Объект» → «Черный список»
2. Нажмите **«Добавить»** → введите номер автомобиля

**Результат:** При попытке создать пропуск на этот номер — предупреждение и блокировка сохранения

**Важно:** С правовой точки зрения полностью блокировать въезд собственнику на его же территорию — не совсем законно.

### Модуль Баланс и Правила

**Назначение:** Виртуальный баланс для учёта «стоимости» пропусков. Используется для внутреннего контроля или взимания платы с пользователей.

**Важно:** Баланс — **виртуальный**, не привязан к реальному эквайрингу. Деньги существуют только внутри системы. Подключение баланса — через техподдержку.

#### Баланс

- Видят только сотрудники-администраторы (пользователи в приложении баланс не видят)
- **Overdraft предусмотрен** — пользователь может уйти в минус
- Пополнение баланса — вручную администратором

#### Правила списания

**Назначение:** Условия, при которых с баланса адреса/пользователя списывается сумма.

**Что делать:**
1. Раздел «Объект» → «Правила»
2. Создайте правило: выберите условие (тип транспорта / адрес / пользователь / группа пользователей)
3. Выберите тип пропуска
4. Укажите номинал списания
5. Нажмите **«Сохранить»**

**Пример:** При создании разового автомобильного пропуска на адрес 7 — списать 100 рублей.

**Использование для Кандерсон:**
- Потенциально можно использовать для учёта «злоупотребляющих» пользователей с большим количеством гостей
- В конце месяца — выставить счёт на основе «потраченного» баланса

---

### Модуль Группы адресов

**Назначение:** Задать ограничения на типы пропусков для группы адресов (например, на коммерческие объекты — только разовые пропуска).

**Важно:** Это **новый модуль** (на момент обучения — несколько месяцев), функционал ещё развивается.

#### Создание группы адресов

**Что делать:**
1. Раздел «Объект» → «Группы адресов»
2. Нажмите **«Создать»**, задайте название
3. Выберите типы пропусков, которые разрешены для этой группы
4. Добавляйте адреса: введите часть названия → выберите из выпадающего списка → повторите для каждого адреса
5. Нажмите **«Сохранить»**

**Результат:** Для всех адресов группы действуют указанные ограничения типов пропусков

**Ограничения модуля:**
- **Нет массового добавления** адресов через запятую или копированием — только по одному
- **Группа адресов не отображается** в колонке модуля «Адреса» (пожелание передано в разработку)
- Чтобы убрать адрес из группы — зайти в группу и удалить через крестик

---

### Модуль Рассылка

**Назначение:** Массовые уведомления пользователям (информационные сообщения, оповещения).

**Важно — известные проблемы на Android:**
- **Push-уведомления не работают** на Android (даже при включённых разрешениях в настройках)
- **Тема запроса не отображается** у пользователя Android — видно только ответ администратора
- **Счётчик новых сообщений** на колокольчике не появляется на Android
- На **iPhone** всё работает корректно

Эти проблемы известны команде разработки PASS24 и находятся в работе, но исправление требует времени.

---

### Модуль Отчёты

**Назначение:** Статистика и выгрузка данных по пропускам, пользователям и адресам.

#### Два формата отчётов по пропускам

| Формат | Где | Период | Содержит |
|--------|-----|--------|---------|
| **События пропусков** | Модуль «Пропуска» → значок облака | до 31 дня | Дата/время въезда-выезда, инициатор события, тип пропуска |
| **Отчёт по пропускам** | Модуль «Отчёты» | до 3 месяцев | Только статистика: сколько пропусков создано, кем, на какой адрес — без времени въезда/выезда |

#### Другие типы отчётов

- **Выгрузка пользователей** — список всех пользователей объекта с адресами привязки
- **Выгрузка адресов** — история изменений по адресам (блокировки, добавления, удаления) за период

#### Глубокий архив (более 31 дня для событий)

Запрос в техподдержку: формат отчёта будет идентичным, но покрывает любой период.

**Важно:** Данные **удалённых пользователей** сохраняются в отчётах — при экспорте за период, когда пользователь был в системе, его данные и события будут включены в отчёт.

---

### Функция Приглашения

**Назначение:** Пользователь отправляет приглашение гостю через мобильное приложение. Гость заполняет данные, и пропуск создаётся автоматически.

**Особенности:**
- Пропуск создаётся **от имени пользователя**, отправившего приглашение
- Никакой метки «создано по приглашению» нет — это обычный разовый пропуск
- Гость не может указать срок действия, превышающий установленный лимит (появится ошибка)

---

### Передача учётных данных (ограничения системы)

**Текущее состояние:**
- Количество **одновременных сессий не ограничено** — можно войти с нескольких устройств под одним аккаунтом
- Ограничение на передачу учётных данных другому пользователю — **в разработке** (точные сроки не определены)
- Отследить вход с разных устройств — возможно через разработчиков (логи системы)

**Для случаев контроля:** Можно сделать запрос в техподдержку для анализа логов (OS устройств, версии приложений).

## Часто задаваемые вопросы (FAQ)

### Вопрос 1: Можно ли скрыть номер телефона администратора от пользователей?

**Ответ:** Убрать полностью нельзя — поле обязательное. Замените на «липовый» номер (нули или девятки): система работает нормально, пользователи увидят этот номер.

---

### Вопрос 2: Можно ли ограничить передачу учётных данных между устройствами?

**Ответ:** На текущий момент нет — количество сессий не ограничено. Это находится в разработке. Для временного доступа используйте доверенность. Отследить использование с нескольких устройств — возможно через запрос к разработчикам.

---

### Вопрос 3: Как заблокировать адрес? Нет отдельной кнопки «Заблокировать»

**Ответ:** Адрес блокируется только через редактирование: «Адреса» → три точки → «Редактировать» → «Блокировка адреса». Чтобы заблокировать конкретного пользователя на адресе — в том же редактировании нажать замочек напротив его имени.

---

### Вопрос 4: Лимит пропусков — это лимит в день или в месяц?

**Ответ:** Ни то, ни другое. Лимит работает иначе: если лимит = 1, пользователь не сможет создать новый разовый пропуск, **пока не будет закрыт предыдущий**. Как только предыдущий закрылся — можно создавать следующий.

---

### Вопрос 5: Как выгрузить отчёт за период больше 31 дня?

**Ответ:** Только через запрос в техподдержку. Формат отчёта будет идентичным, просто с более широким диапазоном дат. Разработчики делают это быстрее, чем автоматический экспорт.

---

### Вопрос 6: Что происходит с пропуском, когда заканчивается его время (машина ещё не выехала)?

**Ответ:** Зависит от настройки в «Объект» → «Настройки». Вариант «висит в просроченных»: пропуск попадает в раздел просроченных и автоматически закрывается, как только смениь статус на «вне территории». Это позволяет зафиксировать реальное время выезда.

---

### Вопрос 7: Видно ли в разделе «Пользователи», что пользователь добавлен по доверенности?

**Ответ:** Нет, в разделе «Пользователи» нет такой отметки. Для проверки — смотреть раздел «Доверенности», там указано ФИО доверенного лица.

---

### Вопрос 8: Что происходит с пользователем при закрытии доверенности?

**Ответ:** Пользователь удаляется из системы, все его активные пропуска закрываются. Его данные и события по пропускам сохраняются в отчётах за период присутствия.

---

### Вопрос 9: Удалили пользователя в середине месяца. Появится ли он в отчёте за этот месяц?

**Ответ:** Да. Все его данные за период, когда он был в системе, сохраняются и будут отображаться в отчёте за этот интервал.

---

### Вопрос 10: Push-уведомления не приходят на Android — как исправить?

**Ответ:** Это известная проблема на Android. Не помогает ни перезагрузка, ни включение разрешений. Исправление находится в работе у разработчиков PASS24. На iPhone работает корректно.

---

### Вопрос 11: Если пропуск создан по приглашению, это как-то помечается?

**Ответ:** Нет. Пропуск создаётся как обычный разовый от имени пользователя, отправившего приглашение, без специальных меток.

---

## Типичные ошибки и их решение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Нет кнопки «Заблокировать» у адреса | Адрес блокируется иначе, чем пользователь | Адреса → три точки → Редактировать → Блокировка адреса |
| Настройки не применяются | Не нажали «Применить» после изменений | В каждом разделе настроек объекта нажмите «Применить» |
| Нельзя закрыть пропуск | Пропуск имеет статус «на территории» | Сначала нажмите «Гость уехал», затем закрывайте |
| Накопились тысячи просроченных пропусков | Выбрана настройка «продлевать на час» | Сменить на «висит в просроченных» или периодически закрывать вручную |
| Новая подгруппа не отображается при создании сотрудника | Кэш страницы | Обновите страницу браузера |
| Нельзя продлить доверенность | Редактирование доверенностей не предусмотрено | Создайте новую доверенность с нужными датами |
| Пользователь не может создать второй разовый пропуск | Лимит пропусков = 1 на пользователя | Дождитесь закрытия предыдущего пропуска |

## Контрольный чек-лист

### При запуске системы

- [ ] Номер телефона объекта настроен (реальный или «липовый»)
- [ ] Сотрудники (охрана, администраторы) добавлены с правильными группами и правами
- [ ] Адреса загружены (через Excel или вручную)
- [ ] Пользователи добавлены и привязаны к адресам
- [ ] Настройки объекта сохранены: лимиты пропусков, максимальный срок, тип пропуска при истечении
- [ ] Разрешения для пользователей настроены (разовые/временные/постоянные)
- [ ] Запрос на самостоятельное присоединение — включён или отключён по требованию

### При работе с пропусками

- [ ] Постоянные пропуска одобряются только через запросы
- [ ] Для закрытия постоянного пропуска: сначала «Гость уехал» → потом «Закрыть»
- [ ] Просроченные пропуска периодически проверяются и закрываются

### При работе с доверенностями

- [ ] Доверенность создана с правильным периодом (точное время при необходимости)
- [ ] По окончании доверенности пользователь удалён и пропуска закрыты (автоматически)
