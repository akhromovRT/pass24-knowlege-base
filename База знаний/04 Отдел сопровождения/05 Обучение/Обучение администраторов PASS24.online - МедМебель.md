## Краткое описание

Данный документ содержит структурированное обучение по веб-интерфейсу PASS24.online на основе записи встречи от 23.09.2025 для объекта «МедМебель» (адрес Индустриальная 1а, один адрес в системе). В документе рассмотрены все основные модули системы. Особенность обучения — практическое тестирование функций прямо в процессе встречи, фиксация двух багов интерфейса (опции объекта не отображаются, русские буквы при режиме «по запросу»), а также детальное объяснение работы Telegram-бота для заказа пропусков и функции приглашений из мобильного приложения.

### Модуль Сотрудники

**Назначение:** Сотрудники — администраторы системы с доступом в веб-интерфейс. Пользователи мобильного приложения — отдельная сущность, они в этом модуле не добавляются.

#### Создание сотрудника

**Что делать:**
1. Нажмите **«Новый сотрудник»**
2. Заполните: ФИО, email, пароль
3. Обязательно поставьте **галочку напротив вашего объекта**
4. Нажмите **«Сохранить»**

**Где:** Раздел «Сотрудники», кнопка «Новый сотрудник»

**Результат:** Сотрудник добавлен; данные для входа (email + пароль) передаются через мессенджер или вручную — никакого письма на почту при создании не приходит

**Важно:**
- Email — это логин для входа в систему
- Email не обязан быть реальным, но если он выдуманный — при утере пароля восстановить его дистанционно невозможно. Придётся менять пароль вручную через редактирование учётки
- Для охраны без корпоративной почты можно придумать любой email; при утере пароля просто поменяйте его через редактирование

#### Смена пароля сотрудника

**Что делать:**
1. Три точки напротив сотрудника → **«Редактировать»**
2. Нажмите **иконку карандаша** рядом с полем пароля
3. Введите новый пароль
4. Нажмите **«Сохранить»**

**Где:** Раздел «Сотрудники», три точки → «Редактировать»

### Модуль Права

**Назначение:** Создание групп прав для разграничения доступа сотрудников к модулям системы.

#### Создание подгруппы охраны

**Что делать:**
1. Нажмите **стрелочку** рядом с группой «Администраторы» — выберите **«Создать подгруппу»**
2. Введите название — например, **«Охрана»**
3. Нажмите **«Сохранить»** (только один раз — кнопка может подвисать; нажали один раз и ждите 15–30 секунд)
4. Нажмите **шестерёнку** рядом с созданной группой «Охрана»
5. Пройдитесь по каждому модулю и настройте права

**Рекомендуемые права для охраны:**

| Модуль | Настройка |
|---|---|
| Сотрудники | Запрещён |
| Права | Запрещён |
| Пользователи | Разрешён (только просмотр) |
| Адреса | Разрешён (только просмотр) — **обязательно** |
| Пропуска | Разрешён (просмотр + смена статуса + создание разовых) |
| Доверенности | Запрещён |
| Рассылка | Запрещён |
| Отчёты | Запрещён |
| Сканер QR-кода | На усмотрение (если будет СКУД) |
| Всё остальное | Запрещён |

6. Нажмите **«Применить»** → **«Сохранить»**

**Где:** Раздел «Права», стрелочка у группы → «Создать подгруппу»

**Важно:**
- Для охраны обязательно открыть доступ к модулю **«Адреса»** — без него охранник не сможет выбрать пользователя при создании пропуска (поле будет пустым)
- После настройки прав вернитесь в «Сотрудники» → три точки напротив охранника → **«Редактировать»** → смените группу с «Администраторы» на **«Охрана»**

### Модуль Пользователи

**Назначение:** Управление людьми, которые пользуются мобильным приложением для заказа пропусков.

**Ключевое разграничение:**
- **Сотрудники** (раздел «Сотрудники») → работают в **веб-интерфейсе**; логин — email
- **Пользователи** (этот раздел) → работают в **мобильном приложении**; логин — номер телефона

#### Добавление пользователя вручную

**Что делать:**
1. Нажмите **«Добавить»**
2. Заполните: ФИО, номер телефона (формат **+7...**), email (необязательно)
3. Выберите **группу** (при необходимости)
4. Присвойте **адрес** (например, Индустриальная 1а)
5. Нажмите **«Сохранить»**

**Где:** Раздел «Пользователи», кнопка «Добавить»

**Важно:**
- После добавления пользователь **не получает автоматического уведомления** — вы сами передаёте ему ссылку на приложение
- Первый вход: пользователь нажимает **«Забыли пароль»**, вводит номер телефона → приходит SMS с кодом → задаёт новый пароль

#### Группы пользователей

Группы — это внутренняя пометка (например, «Арендаторы», «Сотрудники», «VIP»). Они не влияют на функционал, только помогают сортировать и фильтровать список. Создаются через кнопку **«Создать группу»**.

### Модуль Пропуска

**Назначение:** Управление всеми пропусками на объект.

#### Типы пропусков

| Тип | Когда закрывается |
|---|---|
| **Разовый** | После полного цикла: въезд → выезд. Или по истечении срока действия. |
| **Временный** | По истечении заданного срока (неограниченное число въездов в этот период) |
| **Постоянный** | Только вручную |

**Как различить типы в интерфейсе:** у разового и временного есть дата начала и конца; у постоянного — даты окончания нет. Тип также отображается в карточке пропуска (поле «Тип пропуска»).

#### Создание пропуска через веб-интерфейс

**Что делать:**
1. Перейдите в раздел **«Пропуска»**
2. Нажмите **«Создание нового пропуска»** (большой плюс)
3. Выберите адрес и пользователя
4. Выберите тип пропуска, тип транспорта, введите марку и номер авто
5. Укажите дату и время (для разового и временного)
6. Нажмите **«Сохранить»**

**Добавить гостя:** На одну поездку можно добавить нескольких человек сразу. При заполнении формы нажмите **«Добавить гостя»** — поля для следующего человека добавятся автоматически, и данные о дате/времени подтянутся с предыдущего.

#### Несколько пропусков на одного человека

На одного пользователя можно создавать неограниченное число пропусков — на разные автомобили. Просто создавайте новый пропуск для того же пользователя.

#### Закрытие пропуска

**Правило:** Пропуск нельзя закрыть, пока он в статусе **«На территории»**.

**Что делать:**
1. Нажмите на пропуск → откроется боковое окно
2. Если статус «На территории» — нажмите **«Уехал»** (смена статуса)
3. После смены статуса на «Вне территории» — нажмите **«Закрыть»**

**Разовый пропуск** закрывается автоматически после события «Уехал» — отдельного закрытия не нужно.

#### Редактирование пропуска

Редактирование доступно **только до нажатия «Приехал»**. После фиксации события все поля блокируются — это намеренная защита от подмены данных.

#### Массовое закрытие пропусков

**Что делать:**
1. Нажмите иконку **замочка** (режим массового закрытия)
2. Поставьте галочки напротив нужных пропусков или нажмите **«Выбрать все найденные»**
3. Нажмите **«Закрыть выбранные»**

**Ограничение:** Максимум **60 пропусков** за одну операцию.

#### Поиск закрытых пропусков

По умолчанию закрытые пропуска **не отображаются** в списке. Чтобы найти закрытый пропуск:

**Что делать:**
1. В блоке фильтров поставьте галочку **«Закрыт»**
2. Нажмите поиск — закрытые пропуска отобразятся в общем списке

#### Экспорт событий пропусков

**Что делать:**
1. Нажмите **иконку облака со стрелкой** («Экспортировать события пропусков»)
2. Укажите **период** (максимум 31 день)
3. При необходимости выберите **пользователя** (или оставьте пустым — для всех)
4. Нажмите **«Отправить»**

**Результат:** Excel-отчёт приходит на почту учётной записи. Содержит: дата/время въезда и выезда, пользователь, номер автомобиля, кто инициировал событие.

**Инициатор событий в отчёте:**
- **Учётная запись сотрудника** — охранник вручную нажал «Приехал/Уехал»
- **Интеграция** — камера автоматически распознала номер
- **Робот** — пропуск закрылся автоматически по истечению срока действия

За данными старше 31 дня — обращаться в техподдержку.

### Работа с запросами

**Назначение:** Обработка заявок от пользователей мобильного приложения.

**Важно:** Запросы создаются **только из мобильного приложения**. Из веб-интерфейса создать запрос нельзя.

#### Типы запросов

- **На присоединение** — пользователь хочет подключиться к вашему объекту
- **На пропуск** — пользователь создал пропуск (если в настройках объекта стоит «По запросу»)
- **На доверенность** — пользователь хочет выдать доверенность
- **Постоянный пропуск** — всегда через запросы (в мобильном приложении создаётся через раздел «Запросы» → «+» → «Постоянный пропуск»)

#### Обработка запроса

**Что делать:**
1. В веб-интерфейсе перейдите в раздел **«Запросы»**
2. Нажмите на нужный запрос
3. Нажмите **«Одобрить»** или **«Отклонить»**
4. При отклонении укажите **причину** (пользователь её увидит)

**Где:** Раздел «Запросы»

**Результат:** При одобрении пропуск становится активным; при отклонении пользователь получает уведомление с причиной. В истории запроса сохраняется, кто и когда принял решение.

### Модуль Доверенности

**Назначение:** Временный доступ к мобильному приложению для другого человека (доверенного лица).

**Практический пример:** Сотрудник на стажировке 3 месяца. Создайте ему доверенность на этот период — он сможет заказывать пропуска через мобильное приложение. По истечении срока он автоматически удаляется из системы, и все его активные пропуска закрываются.

#### Создание доверенности (администратором)

**Что делать:**
1. Перейдите в раздел **«Доверенности»**
2. Нажмите **«Создать»**
3. Выберите пользователя, от имени которого создаётся доверенность
4. Укажите **период действия** (дата начала — дата окончания)
5. Введите **ФИО и номер телефона** доверенного лица
6. Нажмите **«Сохранить»**

**Где:** Раздел «Доверенности»

**Результат:** Доверенное лицо может авторизоваться в мобильном приложении с теми же правами, что у пользователя-доверителя. По окончании срока — автоматически удаляется.

**Важно:** Настройки максимального срока доверенности — в разделе «Объекты» → «Настройки».

### Модуль Объекты: настройки

**Где:** Раздел «Объекты» → выбрать свой объект → вкладка «Настройки»

#### Номер телефона объекта

Номер, который видят пользователи мобильного приложения при выборе объекта. Рекомендуется указать контакт ответственного за PASS24 (секретарь, администратор, горячая линия).

**Что делать:** Нажмите **«Изменить»** → введите номер → нажмите **«Сохранить»**.

#### Опции объекта (типы визитов)

В разделе настроек можно включить или отключить типы визита (например, «Доставка», «Осмотр специалиста», «Строительная техника» и т.д.). Пользователь может выбрать опцию при создании пропуска в мобильном приложении как дополнительную пометку.

**⚠️ Известный баг (на момент обучения 23.09.2025):** Выбранная опция объекта **не отображается** в карточке пропуска и в разделе «Запросы». Информация передана в отдел разработки для исправления.

**Обходное решение:** Используйте **«Типы транспорта»** — они отображаются корректно и создают аналогичную классификацию.

#### Работа с пропусками: лимиты и разрешения

**Лимиты пропусков:**
Ограничивают максимальное количество одновременно активных пропусков данного типа **во всей системе объекта**.

Например: лимит разовых автомобилей = 50 означает, что в системе не может быть более 50 одновременно активных разовых пропусков. При попытке создать 51-й — выдаётся ошибка.

**Режимы создания пропусков** (для сотрудников и пользователей раздельно):
- **Разрешить** — пропуск сразу становится активным
- **По запросу** — пропуск попадает в раздел «Запросы» для одобрения
- **Запретить** — создание данного типа пропусков недоступно

**Постоянные пропуска от пользователей** — всегда только «По запросу» (это нельзя изменить для пользователей; для сотрудников настраивается свободно).

**⚠️ Баг (на момент обучения 23.09.2025):** При режиме «По запросу» номера автомобилей нужно вводить **только русскими буквами** (латинские не принимаются). Баг передан в разработку, исправление ожидалось в течение нескольких дней.

#### Обязательность данных при создании пропуска

- **Марка автомобиля обязательна** — ползунок «Марка автомобиля обязательна при создании»
- **Формат номера обязателен** — ползунок «Формат номера автомобиля обязателен» (буквы, цифры, регион)

При включённых ползунках пропуск без марки или без полного номера создать не получится.

#### Поведение просроченного пропуска

Три варианта при истечении срока действия (если статус «На территории»):

1. **Перевести в просроченные** — пропуск висит в списке красным; охрана видит и выпускает вручную. ⚠️ Не рекомендуется — накапливаются тысячи просроченных пропусков, система тормозит.
2. **Продлевать на 1 час** — пропуск автоматически продлевается на час до смены статуса. Актуально для платных въездов.
3. **Принудительно закрыть** — пропуск закрывается немедленно, охрана выпускает вручную через смену статуса. Рекомендуется для большинства объектов.

**Совет:** Если оставить «Перевести в просроченные» — охрана может при пересменке фильтровать: убрать галочки «На территории», «Вне территории», «Закрыт», оставить только **«Просроченные»** — увидит все незакрытые пропуска.

#### Максимальный срок действия

- **Разовый:** рекомендуется 12 или 24 часа
- **Временный (многоразовый):** на усмотрение; пересчитайте дни в часы (24 часа × дней)

### Типы транспорта

**Назначение:** Создание классификации транспорта для отображения при создании пропуска.

**Что делать:**
1. В разделе «Объекты» → «Настройки» перейдите на вкладку **«Типы транспорта»**
2. Нажмите **«Добавить»**
3. Введите **название** (например: «Грузовой», «Легковой», «Строительная техника», «Фура»)
4. Укажите **сортировку** (число определяет порядок в списке; 1 = выбирается по умолчанию)
5. Нажмите **«Сохранить»**

**Результат:** При создании пропуска в мобильном приложении или веб-интерфейсе — доступен выбор типа транспорта из вашего списка.

**Практический пример МедМебель:** Добавлены «Грузовой», «Легковой», «Строительный» (сортировка 1, 2, 3 соответственно). При создании пропуска по умолчанию выбирается «Грузовой».

### Чёрный список

**Назначение:** Запрет создания пропусков на конкретные автомобильные номера.

**Что делать:**
1. В разделе «Объекты» → «Настройки» перейдите на вкладку **«Чёрный список»**
2. Нажмите **«Добавить»**
3. Введите полный ГРЗ: буквы, цифры, регион
4. Нажмите **«Сохранить»**

**Результат:** При попытке создать пропуск на этот номер — ошибка «Автомобиль находится в чёрном списке на этом объекте».

### Баланс и правила

**Назначение:** Внутренняя учётная система для отслеживания платных въездов.

**Важно:** Баланс подключается **только через техподдержку** — самостоятельно в веб-интерфейсе настроить не получится (при попытке сохранить — ошибка).

**Как работает:**
1. Техподдержка подключает модуль баланса и выбирает тип (по пользователю, по адресу)
2. Вы устанавливаете начальный баланс (например, 15 000 руб.)
3. В разделе **«Правила»** создаёте правило списания: тип транспорта → тип пропуска → сумма (например, «Грузовой + разовый → 500 руб.»)
4. При создании пропуска по этому правилу — сумма автоматически списывается с баланса

**Overdraft:** Предусмотрен — баланс может уйти в минус. Система продолжает работать при отрицательном балансе.

**Где:** Раздел «Объекты» → «Настройки» → вкладки «Баланс» и «Правила»

### Модуль Рассылка

**Назначение:** Отправка push-уведомлений пользователям мобильного приложения.

**Что делать:**
1. Перейдите в раздел **«Рассылка»**
2. Нажмите **«Создать»**
3. Выберите **тип рассылки:**
   - **По объектам** — всем пользователям вашего объекта
   - **Конкретным пользователям** — выбранным людям (например, должнику)
   - **По адресам** — пользователям конкретного адреса
4. Введите **заголовок** и **текст**
5. Нажмите **«Сохранить»**

**Результат:** Push-уведомление приходит в мобильное приложение. Если текст не умещается — пользователь открывает его в ленте событий приложения.

### Модуль Отчёты

**Типы отчётов:**

| Отчёт | Что показывает | Максимальный период | Получение |
|---|---|---|---|
| **Пропуска** | Созданные пропуска | 3 месяца | Email учётной записи |
| **События пропусков** | Въезды/выезды по пропускам | 31 день | Email учётной записи |
| **Пользователи** | Список пользователей объекта | Текущий момент | Email учётной записи |
| **Адреса** | Список адресов объекта | Текущий момент | Email учётной записи |

**Разница между отчётами «Пропуска» и «События пропусков»:**
- **«Пропуска»** (в разделе «Отчёты») — статистика создания: кто и когда создал пропуск, сколько всего за период
- **«События пропусков»** (кнопка в разделе «Пропуска») — движение: кто когда въехал и выехал

**Практическое применение:** Чтобы найти всех пользователей и проверить, кого забыли добавить — выгрузите отчёт «Пользователи» и просмотрите Excel-таблицу.

За данными старше 31 дня для событий — обращаться в техподдержку.

### Приглашения (мобильное приложение)

**Назначение:** Создание ссылки-приглашения для гостя, когда данные его автомобиля неизвестны заранее.

**Как работает:**
1. Администратор (или любой пользователь с мобильным приложением) открывает приложение
2. На главном экране нажимает центральный **«+»** → выбирает **«Приглашение»**
3. Выбирает адрес и указывает **время визита**
4. Нажимает **«Поделиться ссылкой»** → отправляет ссылку гостю любым мессенджером
5. Гость открывает ссылку, заполняет свои данные (ФИО, марка и номер авто)
6. Администратору приходит **запрос на пропуск** — одобрить или отклонить

**Важно:**
- При создании приглашения пользователь сам является ответственным за этот пропуск
- Пропуск по приглашению визуально **не отличается** от обычного разового — никакой специальной метки нет
- Если гость заполнит срок больше допустимого лимита — появится ошибка; гость сам корректирует время
- Создавать приглашения могут **все пользователи** мобильного приложения объекта — ограничений нет

### Telegram-бот для заказа пропусков

**Назначение:** Альтернатива мобильному приложению — заказ пропусков через Telegram.

**Как работает:**
1. Пользователь открывает Telegram-бот по заказу пропусков (ссылку предоставляет менеджер PASS24 после обучения)
2. При первом запуске — **авторизация по номеру телефона** (должен совпадать с тем, что внесён в раздел «Пользователи» в веб-интерфейсе)
3. Открывается **мини-приложение** (Web App) прямо внутри Telegram
4. Интерфейс аналогичен мобильному приложению: выбор типа пропуска, ввод номера авто, указание периода
5. Пропуск создаётся и попадает в систему

**Два бота:**
- **Бот по заказу пропусков** — для создания пропусков (мини-приложение)
- **Бот техподдержки** — для обращений в техническую поддержку PASS24

**Ссылки на ботов** менеджер отправляет на почту после обучения.

**Важно:** Для авторизации в Telegram-боте пользователь должен быть внесён в систему (раздел «Пользователи» в веб-интерфейсе). Если номера телефона нет в системе — авторизация не пройдёт.

## Часто задаваемые вопросы (FAQ)

### Вопрос 1: Email охранника обязателен? Что если у охраны нет корпоративной почты?

**Ответ:** Email обязателен как логин для входа в систему, но он может быть любым — даже выдуманным. Если охрана забудет пароль, и почта выдуманная, восстановить через email не выйдет. Варианты: (1) вы сами меняете пароль через «Редактировать» учётку; (2) создайте общую почту для охраны (например, guard@yourcompany.ru).

---

### Вопрос 2: Почему охрана не может создать пешеходный пропуск?

**Ответ:** Для создания пропуска охраннику нужен доступ к модулю **«Пользователи»** (чтобы выбрать, на кого создаётся пропуск) и к модулю **«Адреса»** (чтобы выбрать адрес). Без доступа к «Адреса» поле адреса остаётся пустым и пропуск не сохраняется. Проверьте настройки прав подгруппы охраны.

---

### Вопрос 3: Можно ли удалить тестовые пропуска, созданные во время обучения?

**Ответ:** Нет. Пропуска нельзя удалить — только закрыть. Вся история хранится в системе в целях безопасности. Закройте тестовые пропуска через кнопку «Закрыть», и через 2–3 дня (или быстрее, при высокой активности) они автоматически уйдут в глубокий архив и перестанут отображаться в списке.

---

### Вопрос 4: Что означает «Робот» в истории событий пропуска?

**Ответ:** «Робот» — это автоматическое закрытие пропуска системой по истечению срока действия. Никаких действий сотрудника не потребовалось — система сама закрыла пропуск по расписанию.

---

### Вопрос 5: Как найти закрытый пропуск — он пропал из списка?

**Ответ:** Закрытые пропуска по умолчанию скрыты. В блоке фильтров включите галочку **«Закрыт»** — закрытые пропуска отобразятся в общем списке. Искать по номеру автомобиля в строке поиска также можно при включённом фильтре.

---

### Вопрос 6: Можно ли редактировать пропуск после того, как нажали «Приехал»?

**Ответ:** Нет. После первого события («Приехал») редактирование блокируется — все поля становятся недоступными. Это сделано намеренно, чтобы предотвратить подмену данных (номера автомобиля, марки и т.д.) задним числом.

---

### Вопрос 7: Как создать несколько пропусков на одного человека (разные машины)?

**Ответ:** Просто создавайте каждый пропуск отдельно, выбирая одного и того же пользователя. Количество пропусков на человека не ограничено.

---

### Вопрос 8: Что такое «Добавить гостя» при создании пропуска?

**Ответ:** Функция для добавления нескольких человек в одну поездку без повторного заполнения всех полей. Нажмите «Добавить гостя» при создании пропуска — появятся поля для следующего человека, дата и время подтянутся автоматически.

---

### Вопрос 9: Как работает Telegram-бот для заказа пропусков?

**Ответ:** В Telegram открывается мини-приложение (Web App). Пользователь авторизуется по номеру телефона (должен быть внесён в систему). Далее — интерфейс как в мобильном приложении: выбор типа пропуска, ввод данных автомобиля, период. Ссылку на бота предоставляет менеджер PASS24 после обучения.

---

### Вопрос 10: Постоянный пропуск создаётся через раздел «Запросы» в приложении?

**Ответ:** Да. Через главный экран (большой «+») постоянный пропуск не создать — там только разовый и временный. Для создания постоянного пропуска из мобильного приложения — перейдите в раздел **«Запросы»** → правый верхний угол «+» → «Постоянный пропуск».

---

### Вопрос 11: Нужно ли уведомлять пользователей о добавлении в систему?

**Ответ:** Система не отправляет уведомлений автоматически. Вы сами передаёте пользователю ссылку на приложение, номер объекта и инструкцию по первой авторизации (через «Забыли пароль» + SMS-код).

## Типичные ошибки и их решение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Создалось несколько одинаковых подгрупп охраны | Нажали «Сохранить» несколько раз (кнопка подвисает при создании подгруппы) | Удалить лишние дубликаты; при следующем создании нажать один раз и ждать 15–30 секунд |
| Охрана не может создать пропуск с выбором пользователя | Нет доступа к модулю «Адреса» в правах подгруппы | В разделе «Права» → шестерёнка группы «Охрана» → открыть доступ к «Адреса» (просмотр) → применить и сохранить |
| Закрытый пропуск не находится через поиск | Фильтр «Закрыт» не включён (по умолчанию закрытые скрыты) | В блоке фильтров поставить галочку «Закрыт» |
| Нельзя закрыть пропуск | Статус пропуска «На территории» | Сначала сменить статус на «Вне территории» → потом закрыть |
| Невозможно редактировать пропуск | Пропуск уже получил событие «Приехал» | Редактирование намеренно заблокировано; исправить данные нельзя; при необходимости — закрыть пропуск и создать новый |
| Опции объекта не отображаются в карточке пропуска/запроса | Известный баг (на 23.09.2025) | Использовать «Типы транспорта» как аналог; ждать исправления от разработчиков |
| При режиме «По запросу» латинские буквы номера не принимаются | Известный баг (на 23.09.2025) | Временно вводить номера только русскими буквами; баг в работе у разработчиков |
