## Краткое описание

Данный документ содержит структурированное обучение по веб-интерфейсу PASS24.online на основе записи встречи от 21.08.2025 для объекта ДНП Артека (номер объекта 2109). Это первое обучение клиента — позднее состоялось второе (09.09.2025). В документе рассмотрены все основные модули системы: сотрудники, права, пользователи, адреса, пропуска, объекты (настройки, КПП, чёрный список, баланс, типы транспорта), доверенности, рассылка, отчёты, работа с запросами. Уникальная особенность — описание функции **«Приглашения»** (создание ссылки для гостя/курьера), а также подробный разбор создания доверенности администратором от имени пользователя.

## Основной контент

### Введение

Инструктор обучает на своём тестовом облаке, показывая все модули. Клиент уже установил мобильное приложение и ознакомился с пользовательским интерфейсом. Административная часть (веб-интерфейс) содержит больше нюансов и настроек.

### Модуль Сотрудники

**Назначение:** Сотрудники — это администраторы системы (главный администратор и помощники). Они могут вносить, добавлять, удалять, редактировать данные и права в системе.

**Права главного администратора:**

- Абсолютно все права на редактирование и изменение системы
- Может добавлять помощников (других администраторов)

#### Добавление нового сотрудника

**Что делать:**

1. Нажмите **«Новый сотрудник»**
2. Заполните данные:
   - **Имя** (обязательно)
   - **Почта** (обязательно) — email должен быть **корректным**, так как вход в систему осуществляется по email. Также используется для восстановления пароля
   - **Пароль** (обязательно)
   - **Номер телефона** (необязательно)
3. Выберите **группу** (администраторы или охрана)
4. Поставьте **галочку напротив объекта**
5. Нажмите **«Сохранить»**

**Где:** Раздел «Сотрудники», кнопка «Новый сотрудник»

**Результат:** Сотрудник добавлен и может авторизоваться по email + пароль

#### Редактирование прав сотрудника

**Что делать:**

1. Нажмите **три точки** напротив сотрудника
2. Выберите **«Редактировать права»**
3. Откроются настройки каждого модуля — установите нужные ограничения
4. Нажмите **«Сохранить»**

**Где:** Раздел «Сотрудники», три точки → «Редактировать права»

**Результат:** Права сотрудника обновлены

**Важно:**

- Почта используется для авторизации в веб-интерфейсе — пользователи (жители) авторизуются по номеру телефона через мобильное приложение
- Для редактирования данных (имя, пароль, почта) — три точки → «Редактировать»

### Модуль Права

**Назначение:** Создание групп прав для разделения сотрудников по уровням доступа.

#### Группы и подгруппы

**Что делать:**

1. В разделе «Права» можно создать несколько групп с определёнными правами: **администраторы**, **охрана**, **арендаторы** и т.д.
2. При создании сотрудника — присвойте ему соответствующую группу
3. Для настройки прав группы — нажмите **шестерёнку** у группы

**Где:** Раздел «Права»

**Результат:** Группы прав созданы и настроены

#### Настройка прав по модулям

**Что делать:**

1. Выберите группу, нажмите шестерёнку
2. По каждому модулю выберите: **наследует от родительской группы**, **разрешён** или **запрещён**

**Пример — модуль «Пропуска»:**

- Создание пропуска → **Разрешено**
- Типы пропусков → одноразовые — разрешить, временные — разрешить, постоянные — **запретить**
- Так сотрудники смогут создавать только разовые и временные, а постоянные — только главный администратор

**Важно:** После настройки обязательно нажмите **«Сохранить»** — настройки применяются ко всем сотрудникам группы.

### Модуль Пользователи

**Назначение:** Пользователи — это собственники, жители, которые используют мобильное приложение для создания пропусков. Авторизация — по номеру телефона.

#### Добавление пользователя вручную

**Что делать:**

1. Нажмите **«Добавить»**
2. Заполните данные:
   - **ФИО** — можно указать только имя (полное ФИО необязательно)
   - **Номер телефона** (обязательно, через +7) — это логин для входа в мобильное приложение
   - Почта — необязательно
3. Выберите **адрес** (пользователь присваивается к адресу)
4. Нажмите **«Сохранить»**

**Где:** Раздел «Пользователи», кнопка «Добавить»

**Результат:** Пользователь добавлен в систему

#### Самостоятельная регистрация пользователя

**Что делать (со стороны пользователя):**

1. Пользователь скачивает мобильное приложение
2. Начинает регистрацию
3. Приложение запрашивает **номер объекта** (например, **2109**)
4. Пользователь вводит номер → создаётся запрос на присоединение

**Обработка (со стороны администратора):**

1. Запрос появляется в разделе **«Запросы»**
2. Администратор проверяет, действительно ли это собственник указанного адреса
3. Нажимает **«Одобрить»** или **«Отклонить»**

#### Множественные адреса

**Что делать:**

- Если у собственника **несколько участков** — зайдите в редактирование пользователя и **добавьте ещё один адрес**
- Пользователь сможет создавать пропуска на оба адреса

**Практический пример:** Собственник имеет два дома: в одном живёт сам, второй сдаёт в аренду. Оба адреса привязаны к нему.

#### Блокировка пользователя

**Что делать:**

1. Нажмите три точки → **«Редактировать»**
2. Переместите **ползунок «Блокировка пользователя»**
3. Укажите **комментарий с причиной блокировки** (например, «Нарушение скоростного режима»)
4. Нажмите **«Подтвердить»** → **«Сохранить»**

**Что даёт блокировка:**

- Активные пропуска **продолжают функционировать** — их нужно закрывать вручную
- При попытке создать новый пропуск пользователь получит уведомление о блокировке с предложением обратиться в управляющую компанию
- Пользователь видит причину блокировки

**Снятие блокировки:** Редактировать → переместить ползунок обратно → «Сохранить»

**Важно:** Блокировка **не** закрывает существующие активные пропуска автоматически — их нужно найти и закрыть отдельно.

#### Поиск и настройка отображения

**Поисковая строка:** по фамилии или по номеру телефона

**Шестерёнка:** добавьте отображаемые поля — адреса, блокировки, телефон, email, **статус «Зарегистрирован»**

**Статус «Зарегистрирован»:** Если «Да» — пользователь уже авторизовался в мобильном приложении. Если «Нет» — пользователь добавлен, но ни разу не заходил в приложение. Позволяет отслеживать, кто реально пользуется приложением.

**Фильтры:** по регистрации, блокировке, блокировке адресов, блокировке на адресах.

### Модуль Адреса

**Назначение:** Управление адресами объекта (дома, участки, строения).

#### Добавление адреса вручную

**Что делать:**

1. Нажмите **«Добавить»**
2. Выберите **объект** (ДНП Артека)
3. Город — необязательно
4. Заполните **улицу** и **номер дома**
5. При необходимости: строение, корпус, квартира, офис
6. Нажмите **«Сохранить»**

**Где:** Раздел «Адреса», кнопка «Добавить»

**Результат:** Адрес создан

#### Короткое название адреса

**Назначение:** Внутренняя пометка/комментарий к адресу (например, «КПП транзитное», «Платит с задержками», «Нарушает правила»). Не обязательное поле. Полезно для быстрого поиска и передачи информации новым сотрудникам.

#### Массовый импорт адресов

**Что делать:**

1. Нажмите **«Импорт»** (облачко со стрелочкой)
2. Выберите объект
3. Выберите тип:
   - **Пример без пользователей** — загрузка только адресов
   - **Пример с пользователями** — загрузка адресов вместе с пользователями
4. Нажмите **«Скачать»** — получите Excel-образец
5. Заполните табличку **строго по формату** (колонки не удалять)
6. Загрузите заполненную табличку

**Важно:** Если адресов немного — проще добавить вручную. Формат Excel-таблицы нельзя менять — загружается в том же виде, в каком скачивается.

#### Блокировка адреса

**Полная блокировка:**

- В редактировании адреса активируйте блокировку → **все пользователи** на этом адресе не смогут создавать пропуска именно на этот адрес
- Если пользователь привязан к нескольким адресам — на остальные он создавать пропуска сможет

**Блокировка отдельного пользователя на адресе:**

- В редактировании адреса наведите на **замочек** напротив пользователя → «Заблокировать пользователя на адресе»
- Только этот пользователь заблокирован, остальные на адресе могут создавать пропуска

**Поиск:** в поисковой строке — по номеру дома, названию улицы, пользователю.

### Модуль Пропуска

**Назначение:** Основная рабочая область системы — все пропуска, статусы, фильтрация, экспорт.

#### Создание пропуска

**Что делать:**

1. Нажмите **«Новый пропуск»**
2. Выберите **адрес** и **пользователя**
3. Выберите **тип пропуска**: разовый, временный или постоянный
4. Выберите **тип гостя**: автомобиль или пешеход
5. Для автомобиля: укажите номер автомобиля
6. Нажмите **«Создать»** / **«Сохранить»**

**Где:** Раздел «Пропуска», кнопка «Новый пропуск»

**Результат:** Пропуск создан со статусом «Вне территории»

**Важно:** Администратор может создавать пропуска **от имени любого пользователя** — это полезно, когда у пользователя нет телефона или он просит о помощи.

#### Редактирование пропуска

**Условия:**

- Пропуск можно редактировать **только до первого изменения статуса** (до нажатия «Приехал»)
- После первого события — редактирование **закрывается полностью**

**Причина:** В целях безопасности — чтобы нельзя было фальсифицировать данные задним числом.

**Если нужно исправить номер после въезда:** Закройте текущий пропуск → создайте новый с корректным номером.

#### Смена статуса пропуска

**Что делать:**

1. Найдите пропуск в списке
2. Нажмите **«Приехал»** → статус меняется на «На территории»
3. Нажмите **«Уехал»** → статус меняется на «Вне территории»

**Все события фиксируются:** с какой учётной записи была произведена смена статуса (охрана, администратор, интеграция).

#### Типы пропусков: логика работы

**Разовый пропуск:**

- Приехал → Уехал → пропуск **автоматически закрывается**
- По умолчанию предлагается до конца текущего дня
- В мобильном приложении есть шаблоны: 12 часов, 24 часа

**Временный пропуск:**

- Действует в указанный период
- Можно многократно менять статус (приехал/уехал)
- По истечении срока — действие зависит от настроек

**Постоянный пропуск:**

- Бессрочный, закрывается только вручную
- Всегда создаётся **по запросу** — автоматического режима нет

#### Закрытие пропусков

**Важно:** Пока статус «На территории» — пропуск **невозможно** закрыть. Сначала смените статус на «Вне территории», затем нажмите **«Закрыть»**.

#### Массовое закрытие пропусков

**Что делать:**

1. Отфильтруйте нужные пропуска
2. Появятся **галочки** для выбора
3. Отметьте нужные пропуска
4. Нажмите **«Закрыть выбранные»** → подтвердите

**Результат:** Все выбранные пропуска закрыты одновременно.

#### Фильтрация и поиск

**Фильтры по типу:** постоянные, временные, разовые, на территории, вне территории, просроченные, закрытые

**Поисковая строка:** по номеру автомобиля — охрана вводит номер и моментально находит пропуск

**Практический пример:** При 200 гостевых пропусках в сутки охранник вводит часть номера (например, «123») — система выдаёт все пропуска с этими цифрами. Охранник видит марку и определяет нужный.

#### Экспорт событий пропусков

**Что делать:**

1. Нажмите **«Экспортировать события пропусков»**
2. Выберите **период** (максимум **31 день**)
3. При необходимости: пользователь, адрес
4. Нажмите **«Отправить»**

**Результат:** Отчёт в Excel приходит на email учётной записи.

**Важно:**

- За период более 31 дня — запрос в техническую поддержку (данные хранятся в архиве)
- Ограничение в 31 день — для защиты от перегрузки системы

### Модуль Доверенности

**Назначение:** Временный доступ в систему со стандартным функционалом пользователя на определённый период. Основное применение — арендаторы.

#### Как работают доверенности

**Процесс через мобильное приложение:**

1. Пользователь (собственник) заходит в раздел **«Запросы»** в мобильном приложении
2. Выбирает **«Доверенное лицо»**
3. Заполняет данные: ФИО, номер телефона, период доверенности
4. Запрос поступает администратору

**Обработка администратором:**

1. Запрос появляется в разделе **«Запросы»**
2. Администратор проверяет данные
3. **«Одобрить»** → доверенность активируется
4. **«Отклонить»** → указать причину

#### Создание доверенности администратором

**Что делать:**

1. В разделе «Доверенности» нажмите **«Добавить»**
2. Выберите **пользователя** (собственника, от чьего имени создаётся доверенность)
3. Заполните данные доверенного лица: ФИО, номер телефона
4. Укажите **период активности** доверенности (начало — конец)
5. Нажмите **«Сохранить»**

**Где:** Раздел «Доверенности», кнопка «Добавить»

**Результат:** Доверенность создана. Доверенное лицо авторизуется в мобильном приложении по своему номеру телефона.

**Практический пример:** Пожилой человек или отсутствующий собственник звонит администратору и просит оформить доверенность на арендатора. Администратор создаёт доверенность от имени собственника.

#### Автоматическое закрытие

- По истечении срока доверенности — пользователь-доверенное лицо **автоматически удаляется** из системы
- Все его активные пропуска **закрываются**
- Также можно закрыть доверенность **досрочно**: три точки → «Закрыть»

#### Настройка срока доверенности

**Где:** Настройки объекта, раздел «Доверенные лица»

- **Максимальный срок доверенности** — указывается в днях (полгода, год и т.д.)
- **Создание доверенности только через запрос** — «Да» (администратор одобряет) или «Нет» (автоматически)
- **Лимит активных доверенностей** — максимальное количество одновременных доверенностей

### Модуль Объекты: настройки

**Где:** Выберите объект → откроются все настройки

#### Номер телефона объекта

- Отображается у пользователей в мобильном приложении в разделе «Объекты»
- Рекомендуется указать номер, по которому пользователи могут связаться с управляющей компанией
- Изменение: нажмите **«Изменить»** → введите новый номер → **«Сохранить»**

**Важно:** Если у пользователя меняется номер телефона — ему нужно заново регистрироваться, так как номер телефона является идентификатором пользователя.

#### Работа с пропусками

##### Лимиты пропусков

**Важно:** Лимит действует **на весь объект** (на всех пользователей), не на конкретного пользователя.

**Пример:** Лимит 5 разовых пропусков → из 500 пользователей только 5 одновременно активных разовых пропусков может быть.

##### Разрешения на создание пропусков

**Для пользователей мобильного приложения:**

| Тип пропуска | Опции |
|-------------|-------|
| Разовый автомобильный | Разрешить / По запросу |
| Разовый пешеходный | Разрешить / По запросу |
| Временный автомобильный | Разрешить / По запросу / Запрет |
| Временный пешеходный | Разрешить / По запросу / Запрет |
| Постоянный | Всегда по запросу (нельзя автоматически) |

**Для сотрудников:**

- Аналогично можно настроить: разрешить / запретить / по запросу для каждого типа

**Практический пример из обучения:** Разовые пропуска — **разрешить** (автоматически попадают в систему), временные — **по запросу** (администратор одобряет), постоянные — через запрос (как постоянный режим).

##### Марка автомобиля и формат номера

- **Марка автомобиля обязательна** — ползунок (если неактивен, пропуск без марки)
- **Формат автомобильного номера** — ползунок (если неактивен, можно создать пропуск с номером «432» без региона)

##### Максимальный срок действия пропусков

- **Разовый** — в часах (0 = без лимита, рекомендуется **24 часа**)
- **Временный** — в часах (неделя = 168, месяц ≈ 720)

**Важно:** Значение указывается **в часах, не в сутках**.

##### Автоматическое действие при истечении срока

**Условие:** Срок пропуска истёк, но статус — «На территории».

| Вариант | Описание | Рекомендация |
|---------|----------|-------------|
| **Просроченный** | Подсвечивается красным | Не рекомендуется — копятся пропуска |
| **Продлевать на 1 час** | Продлевается до смены статуса | Опасно если не контролируется выезд |
| **Закрыть** | Принудительное закрытие | **Рекомендуется** |

**Важно:** Обязательно нажимайте **«Применить»** после изменения настроек.

#### Работа с запросами (настройки)

- **Разрешить запросы на присоединение к объекту** — если отключить, пользователи не смогут самостоятельно присоединиться через мобильное приложение. Должны будут обратиться в управляющую компанию лично.
- **Разрешить запросы на создание постоянных пропусков** — если отключить, пользователи не смогут даже создать запрос на постоянный пропуск
- **Разрешить запросы на создание доверенности** — аналогично
- **Разрешить сообщение в управляющую компанию** — функция обратной связи

#### Типы транспорта

**Что делать:**

1. Нажмите **«Добавить»**
2. Введите название типа (легковой, грузовой, доставка, клининг, мусоровоз и т.д.)
3. Укажите **сортировку в списках** — порядковый номер в отображении

**Применение:** При создании пропуска пользователь выбирает тип транспорта → можно анализировать статистику по типам.

#### Чёрный список

**Назначение:** Список автомобильных номеров, которым запрещён въезд.

**Что делать:**

1. Нажмите **«Добавить»**
2. Введите номер автомобиля с регионом
3. В комментарии — марку и причину блокировки
4. Нажмите **«Сохранить»**

**Результат:** При попытке создать пропуск на этот номер — ошибка. Пропуск не создастся.

**Примечание:** Функция особенно актуальна при автораспознавании номеров через камеру.

#### Баланс

**Назначение:** Виртуальный баланс (не привязан к эквайрингу, списание реальных денег невозможно).

**Типы баланса:**

- На адрес (если несколько пользователей в одном доме)
- На пользователя

**Что делать:**

1. Выберите **тип баланса**
2. Выберите пользователя или адрес
3. Назначьте **текущий баланс** (например, 10 000)
4. Нажмите **«Сохранить»**

**Правила списания:**

1. Перейдите в раздел **«Правила»**
2. Нажмите **«Создать»**
3. Выберите пользователя/адрес
4. Выберите **тип пропуска** (например, разовый)
5. Выберите **условие** (создание, въезд-выезд)
6. Назначьте **сумму списания** (например, 100 руб.)
7. При необходимости выберите **тип транспорта** (например, персонал)

**Результат:** Баланс автоматически уменьшается при выполнении правила.

#### КПП

**Назначение:** Разделение пропусков между сотрудниками на разных въездах.

**Что делать:**

1. Создайте КПП → укажите название (например, «КПП со стороны леса», «КПП со стороны парка»)
2. Добавьте **адреса** к каждому КПП
3. При создании/редактировании сотрудника → выберите **нужный КПП**

**Результат:** Охранник видит только пропуска своего КПП.

**Практический пример:** На Жуковке — два КПП далеко друг от друга. Гости въезжают через одно КПП, собственники через другое. У пользователя адрес дублируется на оба КПП, и при создании пропуска он выбирает, через какой КПП будет въезд.

### Приглашения

**Назначение:** Функция для создания пропуска, когда данные гостя/курьера неизвестны.

**Что делать (пользователь в мобильном приложении):**

1. Вместо создания обычного пропуска выберите **«Приглашение»**
2. Формируется **ссылка**
3. Отправьте ссылку курьеру, доставщику или гостю
4. Гость сам заполняет свои данные (ФИО, номер автомобиля)
5. Нажимает **«Отправить»**
6. В системе создаётся **разовый пропуск** с данными, которые указал гость

**Где:** Мобильное приложение, верхняя позиция «Приглашение» при создании пропуска

**Результат:** Разовый пропуск создан с данными от самого гостя

**Применение:** Когда вы заказали доставку, но не знаете номер автомобиля курьера — просто отправляете ему ссылку, и он сам всё заполнит.

## Часто задаваемые вопросы (FAQ)

### Вопрос 1: Нужна ли электронная почта для пользователей (жителей)?

**Ответ:** Нет. Почта нужна только для сотрудников (администраторов). Пользователи авторизуются в мобильном приложении по номеру телефона.

---

### Вопрос 2: Можно ли добавить пользователя только по имени, без полного ФИО?

**Ответ:** Да, система позволяет создать пользователя с указанием только имени. Полное ФИО необязательно. Но номер телефона обязателен.

---

### Вопрос 3: Может ли администратор создавать пропуска от имени пользователя?

**Ответ:** Да. При создании пропуска выберите адрес и пользователя — пропуск будет создан от его имени. Это удобно, когда пользователь не может это сделать сам.

---

### Вопрос 4: Видит ли заблокированный пользователь причину блокировки?

**Ответ:** Пользователь получает уведомление: «Вы заблокированы, для уточнения причины блокировки обратитесь в управляющую компанию». Детальный комментарий отображается в системе.

---

### Вопрос 5: Что такое «Приглашение» в мобильном приложении?

**Ответ:** Это функция для создания пропуска, когда данные гостя неизвестны. Создаётся ссылка, которую отправляют курьеру/гостю. Гость сам заполняет свои данные, и в системе появляется разовый пропуск.

---

### Вопрос 6: Можно ли ограничить срок действия доверенности?

**Ответ:** Да, в настройках объекта в разделе «Доверенные лица» можно задать максимальный срок доверенности в днях. Ограничение может быть любым — от дней до нескольких лет.

---

### Вопрос 7: Что происходит при изменении номера телефона пользователя?

**Ответ:** Пользователю нужно заново регистрироваться, так как номер телефона является идентификатором в системе.

---

### Вопрос 8: Можно ли создать доверенность от имени пользователя, если он не может это сделать сам?

**Ответ:** Да. Администратор может создать доверенность в разделе «Доверенности», указав пользователя (собственника) и данные доверенного лица. Это удобно для пожилых людей или отсутствующих собственников.

---

### Вопрос 9: Сохраняется ли история переписки в «Сообщение в УК»?

**Ответ:** Да, вся переписка сохраняется в системе. Можно найти запрос по фильтру «Сообщения в УК» и просмотреть полную историю общения с пользователем.

---

### Вопрос 10: Где взять номер объекта для самостоятельной регистрации пользователей?

**Ответ:** В разделе «Объекты» → выберите ваш объект → уникальный идентификатор отображается в карточке (для ДНП Артека — 2109).

## Типичные ошибки и их решение

| Ошибка | Причина | Решение |
|--------|---------|---------|
| Заблокированный пользователь продолжает ездить | Блокировка не закрывает существующие пропуска | Найти и закрыть активные пропуска вручную через фильтр по пользователю |
| Нельзя редактировать пропуск | Пропуск уже сменил статус (нажали «Приехал») | Редактирование невозможно после первого события — закрыть и создать новый |
| Нельзя закрыть пропуск | Пропуск в статусе «На территории» | Сначала сменить статус на «Вне территории», затем закрыть |
| Система подтормаживает | Много просроченных пропусков | В настройках объекта установить «Закрыть» вместо «Перевести в просроченные» |
| Импорт адресов не загружается | Файл не соответствует образцу | Скачать образец, заполнить строго по формату (не менять колонки) |
| Пользователь не может присоединиться | Неправильный номер объекта | Проверить номер в разделе «Объекты» (2109 для ДНП Артека) |
| Пользователь не пользуется приложением | Не прошёл первичную авторизацию | Проверить статус «Зарегистрирован» — если «Нет», пользователь ни разу не заходил |
