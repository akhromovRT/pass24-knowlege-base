## Краткое описание

Документ фиксирует утверждённую тарифную сетку PASS24 для сайта pass24pro.ru и всех коммерческих материалов. Содержит четыре SaaS-тарифа (Базовый / Стандартный / Профессиональный / Мультиобъектный) с ценами, лимитами, матрицей функций, моделью апгрейда, политикой сверхлимитных SMS, каналами поддержки и обязательствами по SLA из регламента технической поддержки. Документ является источником истины — все остальные материалы (сайт, договоры, КП, маркетинг) ссылаются на него, а не дублируют цифры.

#### 7.1. Зачем нужен API — типовые сценарии

API нужен клиентам, у которых уже есть собственная учётная или операционная система (CRM, биллинг, BI, 1С) и которым нужно автоматизировать обмен данными между PASS24 и этими системами без ручного ввода.

| Уровень | Что делает клиент | Типовые сценарии |
|---|---|---|
| **Read-only** (Стандартный) | Только читает данные из PASS24 | Автоматическая выгрузка журнала событий в учётную систему УК, регулярные отчёты по посещаемости в собственный BI, синхронизация справочника жителей в одностороннем режиме |
| **Read / Write + Webhooks** (Профессиональный) | Читает и записывает данные, получает события в реальном времени | Автоматическое создание/блокировка пропусков по статусу оплаты ЖКУ из биллинга УК, отправка события «гость прошёл КПП» в CRM, двусторонняя синхронизация чёрных списков с системами СКУД, реакция охраны на события распознавания номеров через сторонние сервисы |
| **Полный** (Мультиобъектный) | Полный двусторонний обмен с системами УК | Управление мультиобъектным портфелем через внешний интерфейс УК (единый кабинет в собственном LK УК), автоматизация маршрутов пропусков между объектами, полная интеграция с 1С УК на всех объектах, выгрузка консолидированной отчётности в корпоративные BI-системы |

> Интеграции с конкретными системами УК (1С, биллинги, BI) реализуются через API клиента или нашей командой как [платная услуга](#6-интеграции-и-безопасность).

## Методические примечания

### Почему модель «жёсткие лимиты + апгрейд», а не доплата за слоты

Мы сознательно не вводим доплату за дополнительные КПП/админов/охранников. Причины:
1. **Простота биллинга.** Один SKU на тариф проще считать, выставлять, миграции между тарифами прозрачны.
2. **Прозрачность цены для клиента.** Клиент видит фиксированную стоимость и точно знает, когда и сколько заплатит.
3. **Работающий upsell по росту объекта.** Как только клиент упирается в лимит, он получает не «штраф» за слот, а целый пакет новых возможностей — это воспринимается позитивнее.

Решение зафиксировано в [ADR-001: Единая тарифная сетка PASS24 — жёсткие лимиты с моделью апгрейда](../../../agent_docs/adr.md). Альтернативная модель (доплата за ресурсы по аналогии с мобильными операторами) рассмотрена и явно отклонена в разделе «Альтернативы рассмотрены» ADR.

### Требование к продукту: преднастроенные шаблоны облаков по тарифам

Жёсткие лимиты должны быть встроены в **стандартные шаблоны облаков для каждого тарифа** — чтобы менеджеры могли продавать тариф «как есть», а не запускать ручную донастройку с привлечением разработчика. Это операционное требование к продукту: до релиза сетки на сайт `/pricing/` шаблоны должны быть готовы, иначе модель «один SKU на тариф» теряет смысл — каждая сделка превращается в индивидуальную настройку.

### Почему LPR во всех тарифах

Интеграция с LPR — это способность системы принимать данные от ПАК или стороннего LPR. Сама по себе интеграция не требует отдельной подписки: ценность появляется только при подключении ПАК PASS24.auto (или стороннего распознавания). Поэтому мы не дифференцируем тарифы по LPR, а продаём ПАК как отдельный продукт и делаем его почти бесплатным на Базовом (за 1 ₽ при 6-месячной подписке).

### Почему SLA одинаковый для всех тарифов

SLA привязан к **критичности обращения**, а не к тарифу клиента. Это принцип регламента технической поддержки PASS24: клиент с экстренным инцидентом на Базовом тарифе получает те же 4 часа, что и клиент Мультиобъектного. Дифференцируются только каналы коммуникации (чат, телефон, закреплённый менеджер) и объёмы обучения.

### Политика действующих клиентов pass24online.ru

Специальные условия для клиентов, подключённых на pass24online.ru до запуска новой сетки, сохраняются в рамках их действующих договоров. Миграция в новую сетку происходит по инициативе клиента или при следующем продлении — на индивидуальных условиях.
