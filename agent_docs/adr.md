# ADR

## Записи

### [2026-04-24] ADR-001: Единая тарифная сетка PASS24 — жёсткие лимиты с моделью апгрейда

## Статус
Принято

## Контекст
У компании одновременно существовали три несогласованных описания тарифов: страница `pass24online.ru/tarif` (без цен, русские названия), страница `pass24pro.ru/pricing` (цены есть, английские названия, короткие буллеты без матрицы функций), черновик маркетинга v1.2 (русские названия, цены, детальная матрица, но без согласования). В договорах и КП тарифы описывались по-разному. Перед редизайном `/pricing/` pass24pro.ru требовалось зафиксировать единый источник истины.

## Решение
Принята тарифная сетка из четырёх SaaS-тарифов с русскими названиями (Базовый / Стандартный / Профессиональный / Мультиобъектный), жёсткими лимитами по объектам, КПП, администраторам, охранникам и гостевым QR, с переходом на следующий тариф при превышении. Единое обязательство по SLA — по регламенту технической поддержки, без дифференциации по тарифам. Единственный сверхлимит с доплатой — SMS (3 000 ₽ / 1 000 SMS). Интеграция с LPR доступна на всех тарифах через ПАК или сторонние системы. Эталон зафиксирован в документе `База знаний/02 ОП/Продуктовая линейка/Тарифы PASS24.md`.

## Обоснование
- **Жёсткие лимиты вместо доплаты за слоты** — упрощают биллинг (один SKU на тариф), делают цену прозрачной для клиента, сохраняют естественный upsell: превышение лимита даёт не «штраф за слот», а пакет новых возможностей.
- **SLA единый для всех тарифов** — SLA уже привязан к критичности обращения в регламенте техподдержки, а не к деньгам клиента. Дифференцировать по тарифам пришлось бы ломая сам регламент.
- **LPR везде** — интеграция с LPR сама по себе не стоит денег, ценность — в ПАК. Монетизируем железо, а не флаг в тарифе. Промо «ПАК за 1 ₽ при 6-мес подписке на Базовый» делает Базовый точкой входа для сегмента «мне нужно распознавание номеров».
- **Русские названия** — понятнее для целевой УК-аудитории, «Мультиобъектный» сразу объясняет смысл тарифа.
- **Интеграция с 1С / биллингами УК — всегда платная услуга** — устраняет неоднозначное ожидание «подарка» на старших тарифах.

## Последствия
**Положительные:**
- Единый источник истины для всех отделов (ОП, ОС, маркетинг, продукт, разработка сайта)
- Упрощённая модель биллинга — не нужно считать квоты за каждый КПП
- Понятный upsell-маршрут: каждый апгрейд даёт осязаемый пакет новых возможностей
- Прозрачность цены снимает одну из основных блокировок сделки

**Отрицательные / требующие контроля:**
- Клиенты, у которых сейчас «безлимит» на pass24online.ru, на новую сетку не мигрируются автоматически — требуются индивидуальные решения при продлении
- Часть функций в Roadmap (2FA, SSO, white-label, IP-whitelist) пока не реализована в продукте — на сайте их не публикуем до релиза
- Жёсткие лимиты по КПП/охране требуют согласования с ОП: не должны быть слишком узкими (массовый уход с Базового) или широкими (стагнация на Стандартном)
- Реализация жёстких квот в биллинге и админке требует доработки — зафиксировать в roadmap продукта

## Альтернативы рассмотрены
- **Мягкие лимиты с доплатой за сверхлимитные слоты** (например, +1 500 ₽/мес за КПП) — отклонено: усложняет биллинг и размывает upsell-стимул.
- **Дифференцированный SLA по тарифам** (30 мин / 2 ч / 4 ч / 8 ч) — отклонено: противоречит регламенту техподдержки, требует ночной смены для 24×7, не хватает ресурсов.
- **API как отдельный платный модуль, не привязанный к тарифу** — отклонено: API становится естественным upsell-триггером для Профессионального и Мультиобъектного.
- **Английские названия тарифов (LITE / STANDARD / PROF / BUSINESS)** — отклонено: менее понятны для УК-сегмента.
- **Показ цен Мультиобъектного как формулы «базовая + N × доп. объект»** — отложено: оставлена пометка «от 48 990 ₽ + консультация с менеджером» для гибкости в переговорах с УК.
